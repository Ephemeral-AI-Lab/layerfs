02 / OWNERSHIP

Conceptual layers, not microcrates.

Keep the atomic Store and version graph together. Split only where platform behavior genuinely changes.

layerfs-core

Canonical foundation

Object IDs, codecs, FastCDC and persistent extent, namespace, inode and metadata trees.

layerfs-engine

Store + version authority

SQLite publication, integrity, refs, Layers, Branches, deltas, leases and compaction.

layerfs-vfs

Filesystem semantics

Resolver, range I/O, OperationWorkspace, exact diff and capture/refresh planning.

layerfs-mount/fuse

Mounted presentation

Translates FUSE requests into platform-free VFS operations. It does not own storage identity.

layerfs-materialization/apfs

Native presentation

Builds, captures and refreshes real APFS workspaces without changing canonical meaning.

layerfs-sdk

Small public facade

Typed lifecycle calls and receipts. Applications compose the selected workspace driver.

Portable boundary

core, engine and vfs contain no FUSE ABI, APFS syscall, native path authority or platform-specific canonical bytes.

Remote boundary

Add layerfs-service only when remote synchronization is implemented. It wraps engine; it does not depend on mount or materialization.
