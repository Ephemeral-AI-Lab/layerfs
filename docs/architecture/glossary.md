# Glossary

> **Status:** Current architecture guide for LayerFS 2.0.0; maintained with the source.

Every LayerFS term used in these pages, in one table, with the topic that owns it.

Names in `code` are the source's own. Where one word has two meanings in
LayerFS (backend, install, scope), the row gives both.

| Term | Meaning | Defined in |
| --- | --- | --- |
| Acquisition | The working rows and operation record Project Init keeps in the Store's acquisition tables while it imports a folder; they are discarded before anything is published. | [Project Init: import](engine/project-init/README.md#import) |
| Admission | The first-come, first-served turn each Store session gives one caller at a time before its transaction runs. Waiting for it is readiness, not a retry. | [Store: invariants](engine/store/README.md#invariants) |
| Backend | (1) Sandbox backend: how a Sandbox's daemon runs on a machine's kernel, `native` (`host_process`, macOS) or `namespaces` (Linux, and every `lima`, `apple-container` and `docker` machine). (2) Store backend: SQLite or PostgreSQL behind one seam. | [Sandboxes: backends](control/sandboxes/backends.md), [Store: SQLite](engine/store/sqlite.md), [Store: PostgreSQL](engine/store/postgresql.md) |
| Backup | A copy of one whole sqlite Store, with every project in it, held in a bucket as `<prefix>/<file>/store.sqlite`. | [Backups](control/backups/README.md) |
| Base | The committed root a Workspace reads below its overlay: the Branch snapshot it was bound to, then each root a Commit installs. | [Workspace: base](engine/workspace/README.md#base) |
| Binding key | The key a Store is opened with; every open checks the recorded binding and catalog id, and a PostgreSQL schema records it so another home can open it. | [Store: what it does](engine/store/README.md#what-it-does) |
| Branch | A named line of Commits in a project, with a base Layer and an optional head Commit. `main` is not a Branch. | [History: records](core/history/README.md#records) |
| Bridge | `layerfs-bridge`: the wire contract between a controller and a Workspace daemon: the authenticated channel, every control and SDK record, the daemon's private setup and the Store install records. | [Bridge](engine/bridge/README.md) |
| Bucket | A named place the home records where backups are kept, reached through a driver (local folder, MinIO, R2 or S3 API). Drivers know files by name and nothing about Stores. | [Backups: buckets](control/backups/buckets.md) |
| Call table | The 70 calls in 10 families that every front end exposes, with their arguments, and the one dispatcher they all go through. | [Calls](api/calls/README.md), [SDK](api/sdk/README.md) |
| Capture | The Commit step that seals a Workspace's active overlay generation as its published frontier and opens the next one. It copies no rows. | [Commit: what it does](engine/commit/README.md#what-it-does) |
| Commit | An immutable history record: a complete filesystem root, its parent, the base Layer it was built from, an optional second parent and metadata. Also the call (`workspace.commit`) that makes one from a Workspace. | [History: records](core/history/README.md#records), [Commit](engine/commit/README.md) |
| Construction | Building canonical file and tree objects from input and saving them: Init from a native folder, a Commit from its captured generation. A Commit has one construction producer. | [Commit: construction](engine/commit/construction.md), [Project Init: construction](engine/project-init/README.md#construction), [Files: construction](core/files/README.md#construction) |
| Custody | What an operation keeps after a failure whose effect is not settled (a capture, a published Commit, a retained mount owner). While it is kept, the next operation is refused instead of guessed. | [Commit: custody and settle](engine/commit/README.md#custody-and-settle) |
| Daemon | `layerfs-daemon`: the process in a Sandbox that serves its Workspaces to the kernel and runs their Commits. It opens the global Store directly, supervises no commands and serves no Store calls. | [Daemon](engine/daemon/README.md) |
| Disposable profile | The only permitted SQLite Store profile: WAL journal and `synchronous=OFF`. Durable execution is `NOT_RUN — disabled by owner until explicit reauthorization`. | [Store: invariants](engine/store/README.md#invariants) |
| Doctor | `layerfs-control` `doctor/`: read-only checks of a home, its host, machines, Sandboxes, Stores and backups that report what is wrong and the step that fixes it. | [Doctor](control/doctor/README.md) |
| Effective view | What a mounted Workspace shows: its base plus the overlay rows above the installed floor. | [Workspace: the effective view](engine/workspace/README.md#the-effective-view) |
| Exec | `workspace.exec`: the Sandbox runtime runs `bash -c <command>` in a Workspace directory and returns its exit code and output. Optional: file access needs no Exec. | [Sandboxes: what it does](control/sandboxes/README.md#what-it-does), [Daemon channel and exec](control/sandboxes/daemon-channel-and-exec.md) |
| Family | One group of calls in the call table: `project`, `branch`, `commit`, `file`, `sandbox`, `workspace`, `machine`, `store`, `backup`, `logs`. | [SDK: what it does](api/sdk/README.md#what-it-does) |
| Fork | Making a new Branch at a Layer or a Commit: one Branch row, no tree copied. | [Store calls: Branch history](engine/store-calls/README.md#branch-history), [SDK: `branch.fork`](api/sdk/branch.md#branchfork) |
| Forward | A host loopback port carrying a Sandbox daemon's port, so Workspace calls dial the daemon directly instead of going through the worker. | [Workers and reach: forwards](control/machines/workers-and-reach.md#forwards) |
| Frontier | The published frontier: every change filesystem requests have already published to a Workspace's overlay, from any process. A Commit captures exactly this. | [Commit: what it does](engine/commit/README.md#what-it-does), [Overlay lifetimes: generations and frontier](engine/overlay/lifetimes.md#generations-and-frontier) |
| Generation | A numbered set of overlay rows: the active one takes writes, a captured one is sealed for a Commit, and rows at or below the installed floor leave the view. | [Overlay lifetimes: generations and frontier](engine/overlay/lifetimes.md#generations-and-frontier) |
| Genesis Layer | The first Layer of a LayerStack, written by Project Init with the imported root. | [History: records](core/history/README.md#records) |
| Home | `layerfs-home`: the caller's LayerFS folder (`LAYERFS_HOME`, else `~/.layerfs`; absolute) with the records of machines, Stores, projects, Sandboxes and buckets, and their locks, leases and secrets. A worker's root is never treated as a home. | [Home](control/home/README.md) |
| Install | (1) Commit install: advancing a Workspace's base to the published root while rows written after the capture stay. (2) Store install: the one-time stream of a sealed Store file to a daemon. | [Commit: what it does](engine/commit/README.md#what-it-does), [Project Init: seal and install](engine/project-init/README.md#seal-and-install) |
| Intent | The `op` field a multi-step operation writes into its entity's record before its first effect. A live owner makes other operations `Busy`; a gone owner's uncertain intent makes them `Unresolved`. | [Home: the `op` intent](control/home/README.md#the-op-intent) |
| Kernel route | How the kernel reaches a Workspace: a FUSE session (Linux) or a loopback NFSv3 export (macOS). | [Kernel routes](engine/kernel-routes/README.md) |
| Layer | A published root on a project's main line. `branch.publish` adds one; publication is overwrite-only. | [History: records](core/history/README.md#records) |
| LayerStack | One project's linear timeline of Layers, with its Branches and Commits and one allocation scope. | [History: records](core/history/README.md#records) |
| Lease | The file `store/<name>/open/<pid>` a process holds while it uses a Store, taken under the Store lock. Moves, removes and disconnects refuse `InUse` while a live lease exists. | [Home: locks and leases](control/home/README.md#locks-and-leases) |
| Machine | A kernel that Sandboxes and sqlite Stores live on: the built-in `native` and `docker`, or created `lima` and `apple-container` machines. Every machine except `native` on macOS and Linux runs its sqlite Store calls in one worker. | [Machines](control/machines/README.md) |
| `main` | A project's line of Layers (its LayerStack's head Layer). It is not a Branch: it is not mounted or written, only forked from and published to. | [Store calls: Branch history](engine/store-calls/README.md#branch-history) |
| Manifest | The text object, uploaded last under a pieced backup's name, that records the whole file's bytes, sha256 and piece size. | [Buckets: pieces and manifest](control/backups/buckets.md#pieces-and-manifest) |
| Merge | `branch.merge`: a new Branch from two sides, fast-forward or a merge Commit; also the step a Commit takes when its Branch head moved. | [Store calls: Branch history](engine/store-calls/README.md#branch-history), [Compare and merge: merge](core/compare-and-merge/merge.md) |
| Overlay | A Workspace's own SQLite file with its changed metadata, payload and operation records. It is copied from the daemon's template at mount and deleted at terminal unmount. | [Overlay](engine/overlay/README.md) |
| Physical storage, Store, Stores and projects | Three topics in three layers. Physical storage (`layerfs-storage`, core) turns objects into pack records and reads them back. Store (`layerfs-persistence`, engine) is the one database holding those records and history, with one writer. Stores and projects (`layerfs-store`, control) keeps each Store's and project's record in the home and decides where its calls run. | [Physical storage](core/physical-storage/README.md), [Store](engine/store/README.md), [Stores and projects](control/stores-and-projects/README.md) |
| Piece | One fixed-size part, `<name>.piece-NNNNNN`, of a backup too large for one bucket object. | [Buckets: pieces and manifest](control/backups/buckets.md#pieces-and-manifest) |
| Platform | A machine's kind (`native`, `docker`, `apple-container`, `lima`). It fixes the Sandbox backend, the worker's address and what the support table allows. | [Machines: platforms and profiles](control/machines/README.md#platforms-and-profiles), [Platforms](control/machines/platforms.md) |
| Project | A named LayerStack in a Store, written `<store>/<project>`. | [Project Init](engine/project-init/README.md), [Projects](control/stores-and-projects/projects.md) |
| Publish | `branch.publish`: puts a Branch's head Commit on `main` as a new Layer. | [Store calls: Branch history](engine/store-calls/README.md#branch-history), [SDK: `branch.publish`](api/sdk/branch.md#branchpublish) |
| Publish lane | One admission turn plus the Store's cross-process writer (the `flock` on the Store's directory on Linux and macOS; the `store_lane` row on PostgreSQL), held by a Commit across its head check, last merge step and publish. | [Store: the publish lane in a Commit](engine/store/README.md#the-publish-lane-in-a-commit) |
| Reach | How a daemon on a machine dials a PostgreSQL Store: the caller's URL rewritten for that machine's platform, checked once at Sandbox create. | [Workers and reach: reach](control/machines/workers-and-reach.md#reach-reachrs) |
| Sandbox | One daemon started by a backend on a machine, plus the commands run beside it. The daemon serves the Workspaces; the Sandbox runtime owns the commands. | [Sandboxes](control/sandboxes/README.md) |
| Save | A Storage write session: it accepts objects, packs them and `Save::finish` completes them while the Store stays open. | [Physical storage: saves](core/physical-storage/README.md#saves) |
| Scope | (1) Folder scope: a client option `{ project, folder, branch? }` that allows only some calls and rewrites paths and Branch names; it is not filesystem isolation. (2) Allocation scope: the identity range a LayerStack's inode serials are reserved from. | [Calls: folder scope](api/calls/README.md#folder-scope), [History: inode-serial allocation](core/history/README.md#inode-serial-allocation) |
| Seal | Closing a Store's sole session with a checkpoint so no `-wal` or `-shm` remains. `store.create` seals a new empty Store; a live daemon's Store is never sealed. | [Project Init: seal and install](engine/project-init/README.md#seal-and-install), [Store: SQLite lifecycle](engine/store/sqlite.md#lifecycle) |
| Serial | An inode number, unique within its allocation scope and never reused. | [History: inode-serial allocation](core/history/README.md#inode-serial-allocation), [Filesystem trees: directories and inodes](core/filesystem-trees/README.md#directories-and-inodes) |
| Store | `layerfs-persistence`: the one global database, a SQLite file or a PostgreSQL schema, that holds every project's committed history and objects, with one writer at a time. | [Store](engine/store/README.md) |
| Store kind | `sqlite` or `postgresql`. It decides where Store calls run: a sqlite Store's in a process on its machine's kernel, a PostgreSQL Store's in the caller's process. | [Control: where each call runs](control/README.md#where-each-call-runs) |
| Store record | `layerfs-store`: `store/<name>/record.json` in the home, read once into `StoreRecord` with its parsed `StoreRef`; every call on that Store is routed from it. | [Stores and projects: what it does](control/stores-and-projects/README.md#what-it-does) |
| Support table | The one table of platform × host OS × Store kind that allows or refuses a machine or Sandbox, with the reason; `control/SUPPORT.json` is generated from it. Also called the support matrix. | [Platforms: support table](control/machines/platforms.md#support-table-supportrs) |
| Terminal unmount | `workspace.unmount`: detach the kernel mount, drain requests, revoke, close the overlay and Store reader, and delete the overlay file. Committed history is untouched. | [Daemon control calls: unmount](engine/daemon/control-calls.md#unmount) |
| UpToDate | A Commit outcome when nothing changed: no new Commit is made. Also a `branch.publish` outcome when that Commit was already published as a Layer. | [Commit: what it does](engine/commit/README.md#what-it-does), [SDK: `branch.publish`](api/sdk/branch.md#branchpublish) |
| Whiteout | An overlay directory-entry row whose inode is NULL: a name removed from the base. | [Overlay: namespace](engine/overlay/README.md#namespace) |
| Worker | `layerfs worker`, the one process on a machine that runs the machine's Store calls and Sandbox operations for callers outside it. It listens on loopback behind a secret and runs one request per connection. | [Workers and reach](control/machines/workers-and-reach.md) |
| Workspace | A complete mutable filesystem view over one immutable committed root, served by a daemon and changed by any process that sees its mount. | [Workspace](engine/workspace/README.md) |
