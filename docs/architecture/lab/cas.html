Lesson 02 · Content-addressed storage

The key is a proof obligation.

CAS maps an identity to complete canonical bytes. Put, get, and dedup are safe only when every new, fetched, and occupied object is re-authenticated against that identity.

Implemented coreIdentity checks unconditional

Worst and failure cases

Fail closed before publication

Requested ID mismatch

Candidate canonical bytes hash to another ID. Return IdentityMismatch; write nothing.

Unequal incumbent

The occupied key contains different complete bytes. Treat as integrity/collision failure, not overwrite.

Truncated object

Length or exact EOF validation fails even if storage metadata claims the requested length.

Partial segment tail

Unindexed partial bytes cannot become visible. Validate/truncate only owned incomplete tail.

Orphan immutable object

Durable bytes before publication are safe residue; they do not change the head and need separate GC.

Locator corruption

Read bytes at the locator, rehash, and reject. Index presence alone is never content authority.
