## Versioned original startup and path evidence

New E04 records use `cluster-two-job-receipts-v2` and driver version
`e04-original-write-receipts-v2`. Existing v1 data stays valid only under its own
parser and scope. New source preserves original Create/Completion/mutation/error
custody and extends startup with actual filesystem probe count and observed Linux
magic. A missing/failed probe is unavailable, not observed type zero. The actual
UnsupportedFilesystem refusal precedes bulk reservation and SQLite open and leaves
its created empty artifact. The error is not rewritten as resource exhaustion or
an automatic alternate-route selection. Existing shared E01 v1 serialization is
retained; it does not acquire the new E04 field/qualification by inference.

The v2 external path witness must bind all of:

- Original foreground Docker command, explicit CID-file, exact immutable image,
  inspect result, effective process argv/entrypoint, working directory and declared
  environment, plus the actual inspected mounts.
- Binary, assignment/acquisition/base/replacements, identity and output paths
  through their observed repository bind. A prefix guess is insufficient.
- The database argument separately as the exact original guest-local absolute
  path selected before startup. It cannot alias the repository bind, inputs,
  output directory or global Store. The original argv and collector stat are
  never rewritten into a guessed host pathname.
- A pre-start backing witness: owning container/root-layer or volume identity,
  original creation/setup command, actual filesystem type/magic and mount
  context, initial database absence and explicit retention policy. Any setup
  helper/process cost remains visible and no mutable measured database is reused.
- An independent post-exit observation of the same original guest artifact,
  using exact retained container/backing custody. Device/inode/size/blocks are
  compared only within the same observed guest domain. Failed or missing native
  observation remains unavailable and refuses its consistency predicate.
- Any exported database as a distinct logical-byte copy with its own host
  identity and digest. Export never supplies the original allocation, inode,
  disk-range, residency or physical-I/O evidence. Retain the original backing
  until its declared disposition; `--rm` must not destroy the only original.

The pre-consumer fixture bundle independently seals assignment, acquisition,
base/replacements, profile/seed and source/root context as in v1. Later output
rehashing cannot authorize changed inputs. Source/build/binary/driver/observer/
image/cache identities are frozen before that original invocation. External
resource probes remain observations, not calibrated phase peaks or exclusive
ownership assertions.

## Validator and failure scope

Reuse the existing owning validator and fixed-window JSONL iteration. Dispatch
on explicit record/mapping versions, reject mixed versions, unregistered fields,
changed/reordered input/command witnesses and mismatched original guest artifact.
Add negatives for host/guest path substitution, wrong container/volume/FS,
overlaid mounts, reused preexisting database, changed fixture seal and fabricated

The startup filesystem observation is a new supported fact, not complete physical
I/O or per-job statement-family attribution. The eleven v1 gaps remain until
their separate owning instrumentation exists. A complete valid execution may
return narrow write_window_consistency PASS, while whole observation_consistency
remains INCOMPLETE, qualification NOT_EVALUATED, admission false and E1 count zero.
Every failed/refused/cancelled/unrun operation prefix remains recorded with its
original cause, result/source credit and logical-versus-physical cleanup state.

not a numerical treatment or performance baseline. One original invocation per

no unchanged resampling or best-of. The existing 80-second product cutoff and

four-worker profile. No extra constructor or benchmark maintenance pump. Actual
