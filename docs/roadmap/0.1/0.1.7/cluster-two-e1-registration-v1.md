# Cluster-two E1 registration tooling contract v1

> numerical qualification or milestone completion is recorded here.
> Owner: [tracker #307](https://github.com/Ephemeral-AI-Lab/layerfs/issues/307).
> Prepared 2026-10-07, Asia/Singapore.

The committed [implementation plan](../../../../core/docs/issues/307/IMPLEMENTATION-PLAN-S7-S13-20261007.md)
and [performance companion](../../../../core/docs/issues/307/PERFORMANCE-ACCEPTANCE-S7-S12-20261007.md)
authorize E1 registration work. This specification freezes the registration
schema, source-derived predicates and fail-closed admission tooling. It is not a
frozen performance selection with runnable drivers or invented deployment gates.
Before any sample, commit the concrete row specification and its numerical gate
file, admit that exact input, and preserve every omitted sibling as NOT_RUN.

## Scope and authentic routes

The owning entrypoint is the existing
[runner](../../../../core/benchmark/fs-bench-pro/runner.py) `register` command.
It reads or emits registration JSON and validates retained observations. It
does not compile, start product owners, launch Docker, create a Store, execute a
workload, sample a timer, run a verifier or invoke cleanup. There is no additional
generic campaign runner and no registered `run --family` performance route.

The canonical [registry](../../../../core/benchmark/fs-bench-pro/registry/cluster-two-evidence-v1.json)
retains all 27 draft IDs: seven E engine rows, eleven R runtime rows, six Q
scale/pressure rows and three P failure proofs. Q01 belongs to the runtime service
group; Q02–Q06 belong to acquisition. The registry pins the actual current public
operation paths and source fingerprints consulted for them. Its driver fields
remain INCOMPLETE. Source or operation changes require a new frozen registration
identity before admission; a directory or source pin is not route execution.

E01 uses Overlay/daemon observed startup through readiness. E02/E03 use public
BaseView, daemon original Open completion and Workspace bind, without a kernel
mount claim. E04/E05 use ordinary Workspace mutation through daemon namespace
jobs; E06 uses composed public reads; E07 uses exact last-owner release and normal
automatic owner maintenance. R rows use real native SDK Calls and consumer ports,
with one serialized shared connection distinguished from four connections.
Q acquisition uses public Project Init and the provider-owned acquisition port.
P rows retain real socket/device custody and original one-attempt outcomes.
The global Store remains on macOS; Linux Docker owns the disposable Overlay.

## Executable workload and gate definitions

Each row freezes route, workload counts/bytes, operation start and acknowledged
end, queue/delivery scope, complete command, separate verification, release and
automatic drain. Setup and nested attribution cannot replace timed product work.
Each actual row binds the canonical boundary hash and a sealed finite schedule.

E04/E05's [independent workload helper](../../../../core/benchmark/fs-bench-pro/shared/evidence_workload.py)
expands all 1,000 writes at 4,096 bytes, with offset
`4096 * ((104729 * i) mod (B / 4096))`, seed 1 and exact input-byte hashes.
Both cohorts use the same replacement bytes. Its streaming SHA-256 based fixture
generator supplies distinct deterministic payloads for independent preparation;
actual dense native files, acquired bytes and cache attestations are still
required. Generator output cannot establish physical density or saved roots.
The validator refuses changed counts, offsets or replacement hashes. E06 offsets
and truncate/regrow values, Q namespace shape, finite arrival/service schedules
and P failure checkpoints remain explicit required inputs until specified.

The [gate evaluator](../../../../core/benchmark/fs-bench-pro/shared/evidence_gates.py)
uses integer `eq`, `le` and `ge` predicates. Unavailable values remain null with
INCOMPLETE; booleans and negative values cannot stand in for counts. Fixed gates
include zero prohibited replay/refresh/re-stage/fallback, route-derived constructor limits, full
268,435,456-byte daemon reservation, 134,217,728-byte cleanup capacity, zero new
database/schema/root scan/materialization/restoration on repeated bind, bounded
aligned write cells and no inherited payload demand/global Save/history caused
by local writes. The specific cache trace requires 1,000 initial misses, 9,000
subsequent exact hits, one upstream batch and at most 8 MiB charged cache state;
the sequential serial trace requires one 1,024-serial reservation for 1,000
successful creates starting empty. These predicates retain their exact traces
and source assumptions; they are not universal concurrent/refused guarantees.

Construction environment and actual route profiles are separate. Every command
exports `LAYERFS_CONSTRUCTION_WORKERS=1`; ordinary construction retains its
one-worker limit, while Q02–Q06 public native Project Init retains exactly four
constructor threads from `import/files.rs::INIT_WORKERS`, with one Save producer.
Registry source-pin revision 1 explicitly adds that owning source. Report actual
started threads and selected limits separately; a route with no construction may
start zero threads. Native Init's four must never be recorded as one.

Deployment latency, runnable wait, service, queue, debt, aggregate host/Linux
resident capacity, physical peak/final allocation, read/write/copy work, observer
precision and overhead need owning numerical constants. Registration requires
each field in its named unit. For service rows it checks every finite arrival's
timestamp, bytes, class, Workspace and connection, derives offered totals, and
requires numerical per-class minimum completions, refusal envelope, queue/wait/
turn and drain limits. These limits also become executable per-class gates.
Missing constants do not become visual-judgement PASS.

An owning contract supplies a structured `cluster-two-numerical-authority-v1`
artifact whose referenced `limits[anchor]` key contains the exact value, unit,
closed metric meaning and case/profile/route/limit scope. All must match the
selected target. An arbitrary hashed file or nonexistent key is not numerical
authority. Alternatively an untouched eligible matched control may supply
`ceil(control_metric * numerator / denominator) + offset`. The specification
must freeze the chosen integer formula; no default tolerance is supplied by the
tool. The control receipt must record one sample, eligible cache/correctness/
resource/cleanup PASS, the control role and matching profile, route, workload,
cache and observer identities. Candidate-derived/ineligible/mismatched inputs
are refused. Each control metric also carries its value, unit, closed meaning and
matching target scope. An arbitrary integer, byte count or unrelated timing cannot
calibrate a latency limit. The complete numerical definitions are checked against a separate
gate-specification JSON already committed at the recorded specification commit.

## Identity, observation and independent oracle

Each selected row requires exact commit/tree and product/compilation/dependency/
harness/workload/cache/observer manifests; locked release build command, root
Cargo configuration/lock/toolchain, binary hashes, Docker image, architecture and
kernel; actual driver and independent verifier command/artifacts; sealed fixture,
workload and schedule; profile; and a route proof matched to binary, source,
entrypoint and zero forbidden/fallback routes. The checker validates artifact
content hashes under the owning checkout and checks candidate HEAD/tree/status.
Separately owned untracked Markdown notes can be retained only with exact hashes
and explicit independent-note classification; tracked or product changes remain
unsealed. No unrelated file is removed to obtain admission.

Selected route and observer source descriptors must match the registry's pinned
hashes, the declared source inventory, the product inventory for product paths,
and current artifact contents. Observer source selection must use a registered
pin. An observer with no implemented pinned source cannot acquire admission from
an arbitrary file/proof. Source changes require explicit registry-pin advancement;
admission does not silently refresh pins.

The independent oracle is generated from declared inputs. Candidate output never
supplies expected state. Full-root acquisition requires all paths, supported
metadata, payload bytes, raw link targets and hard-link aliases, source removal
and authenticated consumer reads. Other rows retain exact old roots, expected
bytes, namespace isolation, canonical identity, authority, reference closure,
original outcomes, custody, cleanup and global history according to their route.
The oracle command's first executable must be its sealed oracle binary, using
the same rule as the public driver; hashing an unused verifier does not qualify it.
Both use canonical path resolution under the owning root, accepting a `/var` ↔
`/private/var` or symlink alias of that exact artifact while refusing another
executable such as `/usr/bin/true`.

Observers are explicitly scoped to the whole original operation. Overlay
StatementWork/JobWork counts actual attempts/VM/rows/triggers/binds; PayloadWork
covers actual local cell/copy/zero windows; AllocationWork counts range/identity/
freelist work and actual allocation. Native/runtime/global SQL and CanonicalClient
have distinct source scopes. Exact internal pager/device/kernel/whole-operation
copy and external phase residency assembly remain incomplete. A configured cache
or credit allowance is not a whole-system resident bound. EXPLAIN and correlated
actual SQL profiles are both required and sealed; EXPLAIN cannot replace runtime
execution evidence. Observation must not prime a measured cold phase.

Retained resource witnesses require baseline/peak/final bytes, a consistent
strictly increasing timestamp inventory with at least three samples, covered
opened/closed boundaries, and a guaranteed interior sample after propagating
the recorded clock uncertainty. Count, first/last and largest-gap values must
agree with that inventory. A shared clock identity or exact timestamp conversion
through a hashed PASS calibration receipt is required; its bounded error cannot
exceed the frozen clock-error limit. Boundary coverage, interior membership and
maximum gap include conservative uncertainty. Exact sample interval and maximum
gap are frozen. Lifetime peaks and missed boundaries are refused. Sampled peaks retain the
`sampled` label; the checker does not claim continuous maximum coverage. Host and
Linux domains are checked separately. Phase witnesses do not equate logical page
count, requested reservation volume, allocated bytes, RSS and file shrink.

The byte-value inventory has the same cardinality as the timestamps; its first/
last values equal baseline/final, and its maximum supplies the checked peak.
Gated host/Linux peak metrics must equal these witness-derived values. Resident
spread is frozen as `max(sum(owner phase peaks)) - min(sum(owner phase peaks))`
for the declared matched cohort: E04/E05 together, Q02–Q05 together, or an
explicit singleton for other rows. Every operand needs its sealed single-sample
record, checked phase witnesses and matching arm/profile/source/product/binary/
cache/observer identities. Missing operands and invented scalar spread values
remain INCOMPLETE. This is a range of sums of separately observed owner peaks;
sampled values stay sampled, with no simultaneous aggregate-peak claim. A
singleton's derived zero range establishes no cross-size result.
Every operand must also have registration_status PASS. Resolved numerical limits
alone cannot bypass a failed route, cache or other admission check.

## Budgets, cache and outcomes

Default new complete commands are at most 15 seconds, with only Q04/Q06's
prospectively declared 25-second exceptions. Independent verification is at most
9.5 seconds, strictly below 10. Functional commands have explicit 120-second
ceilings; a timeout is FAILED and requires source/output diagnosis. Q05's complete
command budget remains unresolved; no history or old #305 exception is inherited.
Every invocation exports `LAYERFS_CONSTRUCTION_WORKERS=1`, retaining only native
Init's separately supported construction profile. No extra constructor qualifies
a miss. These harness watchdogs do not impose ordinary Bash runtime limits.

Cold rows require an equal phase-specific reset/attestation contract for each
owning source/Store/Overlay/cache domain. E03, R04 and Q01 declare a complete
charged reuse trace. Initial acquisition within such a trace remains timed.
Setup, own writes, preparation or another phase cannot credit a cold phase.
Source uncertainty or asymmetric cache state is INCOMPLETE/INELIGIBLE.

Registration returns PASS only for complete selected inputs. Every sample is
still NOT_RUN with sample_count 0. Retained evaluation reports only per-row
`numeric_gate_status` and overall `retained_numeric_status`, preserving numerical
FAIL/INCOMPLETE and requiring complete registration for numeric PASS. Its schema
is `cluster-two-retained-numeric-v1`; it reports qualification_status NOT_EVALUATED.
It emits no evidence-admission PASS or retained-evidence verdict. Actual completed
outcomes, acknowledged timer boundaries and identity-bound oracle/cache/lifecycle
results are not implemented by this numeric evaluator. Original receipt identity
and prospective declarations cannot establish those results: a failed or
unattempted operation can have passing scalar comparisons without qualified
evidence. One sample
per case/arm, frozen arm order, fresh append-only receipts, worktree-local lock/
targets, independent verifier and no same-worktree build/measurement overlap
remain required for eventual execution by an actual owning family.

Retained observations must bind registry, complete registration, individual row,
source commit/tree, workload, boundaries, observer and driver binary identities.
Their metrics and phase witnesses must exactly equal a hashed raw observation
artifact. Unrelated identities or unsealed edited counters cannot qualify a row.
Each retained row also requires its prospectively frozen source arm and sample
identity, sample_count exactly 1, and the exact ordered public-attempt cardinality.
Every original attempt has a unique ID and hashed original receipt bound to the
same case/source/binary/arm/sample and operation index. Duplicate/reused receipts,
different sample IDs/arms and resampled aggregates are refused. Known E/R/Q/P
call counts come from the registry; mixed-load attempts must cover the entire
frozen offered trace. Remaining custody/release trace counts must be explicitly
frozen before admission.

The eight restored Init speed and strict allocation failures remain FAIL against
same-profile cluster-one-end Project `197d2fb7d`. The six approved history pairs
remain PASS in their acquisition-bypassing scope. Older `7edddbdb8` Service Init
is a distinct comparison. This tool does not replay or promote those receipts,
run optimization experiments, qualify native FUSE/Commit, complete E1/S7/S9 or
authorize reference retirement.
