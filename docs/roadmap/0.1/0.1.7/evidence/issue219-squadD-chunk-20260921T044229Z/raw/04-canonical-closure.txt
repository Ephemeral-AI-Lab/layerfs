## Frozen CDC profile

`core/crates/layerfs-content/src/file/cdc/gear.rs`:

| Constant | Value | Line |
|---|---|---|
| `MINIMUM_CHUNK_BYTES` | 8,192 | 13 |
| `TARGET_CHUNK_BYTES` | 16,384 | 15 |
| `MAXIMUM_CHUNK_BYTES` | 32,768 | 17 |
| `NORMALIZATION_SHIFT` | 2 | 19 |
| `PROFILE_SEED` | 0 | 21 |
| `SMALL_MASK` | `0x0000_d903_0353_7000` (popcount 16) | 23 |
| `LARGE_MASK` | `0x0000_d901_0353_0000` (popcount 12) | 24 |

Hazard rates: `p_small = 2^-16 = 1.526e-5`, `p_large = 2^-12 = 2.441e-4`.
Analytic expected chunk length for incompressible input (mass function over
`[MIN, TARGET)` at `p_small` then `[TARGET, MAX)` at `p_large`):

```
E[L] = 8192 + sum_{t=0}^{8191}(1-p_s)^t + (1-p_s)^8192 * sum_{t=0}^{8191}(1-p_l)^t
     = 19,441.3 B
predicted chunks over 275,564,964 B = 14,174      (continuous-stream model)
observed chunks                     = 14,466     (+2.0% in mean, -2.0% in count)
per-file renewal model (456 restarts) = 14,418    (-0.33% vs observed)
implied mean from the receipt         = 19,049.15 B
```

The per-file model restarts the hash once per file (`Scanner::new`, `gear.rs:56-63`;
`scan` at `gear.rs:75-95` owns one `Scanner` per streamed reader), so each of the 456
chunked files contributes a truncated final chunk. That correction moves the model
from 14,174 → 14,418, against a receipt of 14,466.

**Confidence.** Two independent closures land **exactly** on the receipt's bytes
(23 B and 21 B overheads) and the chunk count lands within 0.33 % of a model built
only from the frozen masks. The size ladder, the cutoff and the chunk partition are
therefore established, not inferred.

**NOT_MEASURED.** The per-chunk length histogram itself. The receipt publishes chunk
*count* and *canonical bytes*; no per-chunk length is recorded in any receipt of this
campaign, and no instrumentation was run.
