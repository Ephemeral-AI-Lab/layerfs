## Why this pair exists

#169's acceptance asks for "existing-or-better qualified localized-edit
latency/storage/memory" (§6 of that issue) and #168 asks that storage/index/column
footprint, memory and speed claims be measured rather than asserted. Until now no
matched arm existed. This pair is the closest legitimate match: the same base bytes,
the same edit tuple, both applying one localized edit in memory through their own
public operation and returning the new root.

## Conclusions

1. **Correctness: reference-equivalent on this shape.** Both arms return the same
   content-addressed root `b6dca354fe1a8e4a9f7a3db9d0d144b0bddc9f5deacef6b7598920087c65207b`
   for the same base and edit, in every observation. This is an independent
   confirmation of reference equivalence *outside* the test fixtures, and it is the
   part of this round that can be used as evidence.
2. **Latency: the gate stays unqualified.** The measured ordering is not stable and
   one sample per arm cannot support either "existing-or-better" or "slower". The
   smallest missing case is an owner-approved campaign with repeated samples (n >= 5)
   per arm on this exact fixture and profile, reporting every sample, before any
   latency claim is made in either direction.
3. **Storage: not a like-for-like comparison.** The reference wrote 5 objects and
   13 826 bytes inside the timed window; the candidate wrote 7 objects and 47 357
   bytes. The difference is dominated by the replacement content, which the candidate
   emits through its consumer inside the window; the reference's write boundary for
   that content was not established by reading its write path, so no storage
   conclusion is drawn. Fixing this needs a byte-accounting boundary that both
   implementations expose, or a read of the reference write path to align them.
4. **Memory: not measured.** Neither arm instruments allocation or resident memory;
   the declared-capacity evidence in the timing round stands for the candidate, and no
   reference memory figure exists. #168's "simultaneous index/codec/SQL memory" gate is
   therefore **unmeasured**, not passed.
