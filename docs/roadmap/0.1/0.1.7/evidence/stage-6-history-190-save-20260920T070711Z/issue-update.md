### What `storage.accept_loop` is made of — and why the write pattern is not yet a target (L50)

Continues L49. L49 removed the read path's pack-acquisition term and left the save flat (+135 / −26 ms), which makes the save the largest single sub-phase (9.13 s of stride10's 16.7 s operation, 18.4 s of stride3's 37.1 s) and the only one with no attribution — L42 refused to treat it because compression, indexing and transaction work were not separated. The product already computes those figures in `SaveOutcome`; the harness published one of them. Evidence: [`stage-6-history-190-save-20260920T070711Z`](https://github.com/Ephemeral-AI-Lab/layerfs/tree/codex/190-pooled-scope/docs/roadmap/0.1/0.1.7/evidence/stage-6-history-190-save-20260920T070711Z).

**Harness-only change, no product line.** `ops/history.rs` (+152 lines): the existing `SaveTotals` accumulator gains `pack_appends`, `commits`, `statements`, `presence_queries`, the `chain.*` and `pool.*` sub-counters and a `rows()` accessor, so each state now publishes 29 `history.state.<n>.save.*` figures. Nothing new is measured — every field comes from the `SaveOutcome` the product already returned. Format deviation recorded rather than swept in: the added code carries 9 rustfmt hunks (the file carried 20); reformatting moves the built binary (embedded `panic!` locations), which would leave the receipts describing a source no longer in the tree, so the measured source is kept as measured.

**Measured, matched arms, identical harness source (seal `264e88c5…`), one sample each.** stride10 operation 19.638 → 16.908 s (**−2.730 s**, reproducing L49's −2.754 s under a different harness source) and stride3 48.638 → 36.810 s (−11.828 s); `storage.accept_loop` +0.030 / −0.085 s. Every state root and content counter equal, both Stores hashing to the recorded constants (`4af37932…` / `f5c7ff5a…`), and **every `save.*` counter identical between arms** — the same work, acquired differently.

**Attribution.** Stride10: 45,239 FULL preparations, 38,230 trials, 107,628 chain objects read and 133.9 MB of encoded bytes read for trials, 48,925 new values, 53,355 reused, 44,331 statements, 45,791 pack BLOB rewrites, 1,149 commits. Per inserted object, early → late: `accept_loop` 93.6 → 212.5 µs (2.27×), **chain objects 1.039 → 2.409 (2.32×)**, **chain edges 0.433 → 1.603 (3.70×)**, while FULL preparations 1.06×, appends 1.07×, statements 1.06×, commits 0.83×. So the save path's **depth term is delta-base acquisition** — the only per-object quantity that grows like the time.

**The write pattern, sized.** 44,141 of 52,032 objects sit in groups of exactly one (the `WholeFile` lane seals on every record by construction), so each placement rewrites the whole pack BLOB, and `write_pack` charges the whole rewritten pack to the transaction's 4 MiB budget, forcing a commit every ~40 appends. That is **4.43 GB rewritten to store 45.3 MB — 97.8×**. A synthetic replay of the exact pattern costs **1.03 s** (0.15 s rebuild + 0.88 s SQLite) — a bound on one pattern, not the product's cost, and around rather than clearly above the one-second bar.

**Decision: no treatment this round.** The two candidates are a ~1.03 s synthetic bound whose fix touches the visibility and atomicity of the open tail, and an unsized depth term; choosing between them on this evidence is the mistake L42 declined to make. The next step is one more attribution layer **with time** — bounded aggregate spans inside the accept path (selection and chain acquisition / compression / placement and write / SQL), identical in both arms and kept separate from unprofiled samples.

**Bonus: the L49 reconciliation gap is explained, and its probe corrected.** A freshly created executable's **first** run costs 0.7–2.0 s on this machine before `main` (1,959.5 / 669.4 ms first against 34.8–38.9 ms afterwards), outside `phases::begin`; L49's start-up probe missed it by running after the first execution. That accounts for L49's `INCOMPLETE` and for both stride10 rows here (2.018 / 1.823 s), while every stride3 row is ~0.04 s because by then both binaries have run once. Both stride10 rows are reported `INCOMPLETE` with a measured, non-product cause, and the operation comparison reproduces L49 within 24 ms. The L49 report carries an appended correction.
