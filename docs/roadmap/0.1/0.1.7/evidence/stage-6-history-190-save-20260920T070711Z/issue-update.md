### stride1 measured: the scaling curve after the treatment, and where its residual depth term lives (L51)

Follows L50 on the same branch. L49 sampled stride10 and stride3 and left **stride1** — the finest end of the scaling curve, the end the whole finding is named for — unmeasured. Both arms are now sampled, same protocol, the same two sealed binaries, and the retained campaign's own declared 720 s diagnostic cap reused unchanged (its stride1 run used 28 % of it).

**The curve, in L47's units.** Operation and ns per changed MB, pre-fix → post-fix: **17 versions** 19.739 s / 52,297,706 → 16.908 s / 44,796,163 (**−14.3 %**); **53 versions** 48.976 / 68,625,861 → 36.810 / 51,579,091 (**−24.8 %**); **157 versions** 146.178 / 84,996,709 → **105.726 s / 61,475,883 (−27.7 %)**. Least-squares slope against ln(versions): **14,706,448 → 7,491,080 ns/MB per e-fold (−49 %)**; finest against coarsest **1.625× → 1.372×**. So the treatment's benefit does grow with version count — as the mechanism predicted — the curve is flattened by about half, and it is **not flat**: at 157 versions a changed byte still costs 1.37× what it costs at 17.

**What was not removed.** At matched changed volume the within-chain depth term barely moved at stride1 — bands 4–7 / 7–10 / 10–14 / 14–22 MB: 1.58 / 1.95 / 1.56 / 1.25× before, 1.54 / 1.84 / 1.54 / 1.32× after (−6 % to +6 %), against −9…−16 % at stride3. Depth elasticity of the state total against ln(state) fell on all three rows (stride10 12.46 → 8.20 M; stride3 17.89 → 11.13 M; stride1 25.33 → **14.95 M** ns/MB per e-fold). So the treatment removed a large term that grows with depth in absolute terms and left the within-chain residual that the bands isolate essentially intact.

**Where the residual is — and it is not a cache.** With the save counters published per state for the first time, at 157 versions per inserted object, early → late: **chain objects read for trials 2.04 → 6.32 (3.09×)** and **chain edges walked 1.25 → 4.54 (3.62×)**, while prefix trials are 1.10×, FULL preparations 1.00×, pack BLOB rewrites 1.05×, INSERT statements 0.98×, commits 0.86×. Totals: 648,299 chain objects and **653.7 MB of encoded bytes read for trials** (stride10 read 107,628 objects and 133.9 MB for 4.6× less content), 84,473 pack appends, 1,797 commits. Per-state elapsed correlates **+0.947** with chain objects, +0.938 with changed bytes, and only +0.444 with objects written. The residual depth term is the trial's acquire-and-compare: a prefix trial must reconstruct the base it compresses against, and at 157 versions the chains are genuinely longer. No cache scope or bound touches it.

**Equivalence and verification.** Every state root and content counter equal; both Stores hash to `1635cf7bbbabdc7f9e4af81ac9c6b6a88f45be35b4100dda0f52394c85dcf418` — the **retained campaign's own stride1 Store**, recomputed from its artifact and used as a cross-round constant, making stride1 the third row whose bytes are provably unchanged by the treatment. Identity-matched verification on both rows inside the 60 s hard budget: **9,996 of 904,143 path-states sampled, 0 mismatches, 0 missing, 0 unexpected**, identical counters between arms, both `g6.*` gates PASS.

**One correction to L50.** L50 claimed first-execution cost "accounts for every observation in the family"; the candidate's stride1 row shows **1,878 ms outside the child's clock on that binary's third execution**, so that is too strong. First-execution cost (measured 0.7–2.0 s) is one demonstrated cause and explains both stride10 gaps and L49's, but a second out-of-clock cost exists and is unidentified. Both stride1 rows reconcile PASS (tolerance wall/50 = 3.2 s against stride10's 0.97 s) and no operation figure is affected.

**Next target, stated for the record.** Not another cache: the acquire-and-compare path of a prefix trial, or the selection policy that decides how deep a chain to build — with the space/time trade declared and both axes reported, since a shallower chain would grow the Store.
