### The depth term was a pack-cache *scope* term, and one scope change removes it (L49)

Follows the scaling handoff. The mechanism was confirmed from counters that already existed **before** any product line changed, then one pre-registered treatment was measured against matched arms. Evidence: [`stage-6-history-190-scope-20260920T062421Z`](https://github.com/Ephemeral-AI-Lab/layerfs/tree/codex/190-pooled-scope/docs/roadmap/0.1/0.1.7/evidence/stage-6-history-190-scope-20260920T062421Z) — mechanism, pre-registration, counters, equivalence, sub-phases, checks, runs.

**Mechanism (confirmed, no new sample).** `Resolver::resolve_charged` built a `PoolReader` once per resolved inode leaf, so its 4 MiB pack cache and 512 KiB value cache died with every leaf, while the decoded-group cache beside it is operation-scoped and is consulted *after* the pack body is acquired. From the retained campaign's own traces and Stores: stride10 **79,784 pack fetches over at most 255 stored packs → ≥ 99.7 % of fetches re-read a pack the same state had already read**, 7,985,771,449 bytes copied = **176.3× the whole pack space**, decoded-group hit rate 0.951; stride3 427,384 fetches over at most 437 packs → ≥ 99.9 % repeats, 25,105,269,671 bytes = **443.6×**. Structural counters do not carry it: chain edges per record call settle at 0.28–0.39 from state 4 on, records per leaf rise 2.2× while bytes copied per leaf rise 54×. It was repeated acquisition of whole committed packs discarded at the per-leaf boundary — not a deeper delta chain.

**Treatment (one change, no bound moved).** The pooled reader's lifetime becomes its calling operation's: `ReadSession` owns one for the whole read operation, the save's own `pool_reader` (already shared by the pooled lane and the depth walk, already released on every pack write) serves `read_batch`/`resolve_location`/selection, `Store::read_batch` keeps a reader for its one wave. Bounds unchanged (4 MiB / 512 KiB, both still released wholesale at the bound), no retained-bytes growth, no instrumentation added, single construction worker untouched. The invalidation contract is stated in code and unchanged: a pack at or below the ceiling a read was authorized under is immutable, the ceiling is re-read per wave, and every pooled consult checks the pack against the current ceiling before the cache answers.

**Measured (one sample per case per arm; baseline = the retained tree at `c4f757514` reusing the campaign's own binary, candidate = that tree + this change, harness source unmodified in both).** Operation (sum of named children): stride10 **19.500 → 16.746 s (−2.754 s, −14.1 %)**, stride3 **48.813 → 37.066 s (−11.747 s, −24.1 %)** — above the pre-registered ≥ 1 s bar on stride10 and no stride3 regression, so **retained**. Localised by the product's own tree: `filesystem` (read/update) −2,909 ms / −11,712 ms, `storage.accept_loop` +135 / −26 ms (noise), `content` flat; per state it grows with depth (stride10 `filesystem` early 158.5 → 116.1, late 760.6 → 475.1 ms). Counters moved exactly as pre-registered: `pack_fetches` 79,784 → **250** (0.003×) and 427,384 → **2,104** (0.005×), `pack_bytes` 7.99 GB → **16.6 MB** and 25.11 GB → **80.2 MB**, `value_group_decodes` 0.517× / 0.498×, while `physical_record_calls`, `physical_group_decodes`, `physical_group_cache_hits`, `chain_edges` and `leaf_requests` are **bit-for-bit unchanged (1.000×)**. The 4 MiB bound does bind (26 / 65 packs fetched in the last state against 255 / 437 stored); the 512 KiB value cache only halves its decodes — recorded as measured, not proposed, because widening it is retained-bytes growth and an owner decision.

**Equivalence.** Every state root and every state content counter equal between arms; both saved Stores hash to the **constants the retained campaign recorded** (`4af37932aa3391b1…`, `f5c7ff5a6b4f0821…`) with equal canonical/value-group inventories. The harness's allocated axis still moves on identical bytes (50,171,904 → 50,249,728; 62,152,704 → 63,160,320), reproducing L47's finding that allocation is a property of extents rather than content.

It is **not credited** — retention rests on the operation, the `filesystem` sub-phase and the counter collapse, all inside the declared phases.
