# A1 — policy and codec diff (v0.1.7 vs v0.1.6)

The report is [`A1-policy-codec.md`](A1-policy-codec.md) in this directory, as the
task's "Write to:" line names it. This file exists only so the squad's generic
`A1.md` path resolves.

Headline: **the v0.1.7 codec parameter set is byte-identical to v0.1.6's and did
not regress** (measured FULL-object rate 0.351858119 vs 0.360035169 B/B =
0.977288, i.e. v0.1.7 is 2.27 % *better*). Three policy defaults did regress
(`metadata_delta_max_depth` 16→8, `METADATA_CLOSURE` 128 KiB→65,536, and the
candidate cache's lifetime session→one save) and none of them can account for the
2.61x Store: their worst-case combined ceiling is 11.69 % of the 79,548,416 B
excess, and the two largest are measured with the *opposite* sign.

90.46 % of the excess is the whole-file lane, and 78.74 % of the whole excess is
one class — 18,820 objects / 212,532,740 canonical bytes that v0.1.6 stored as a
delta against a declared predecessor and v0.1.7 stores as FULL, even though 100 %
of those bases are present in the v0.1.7 Store.
