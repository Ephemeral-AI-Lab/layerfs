## 3. Findings, ordered by severity

**F1 (high, code defect — not run by me). Non-regular-file inodes can acquire a second parent through an update.**
Trigger: an update adds one binding `(parent=P, name=N) -> S` where `S` is an existing Directory or Symlink whose current binding is *not* mentioned in any `DirectoryUpdate` of the same operation.
Observed: `validate.rs:132-160` counts only bindings present in `update.changes` (`additions` map), and the base record contributes only `kind` (`validate.rs:143-148`), so the check `*added > 1` never fires. The operation succeeds and stores `namespace_ref_count = 2` for the directory/symlink (`reduce.rs:509-543`, `zero_count_serials` at `update.rs:411-421` agrees the count is 2). Expected: refused, because `InodeValue::validate(false)` (`inode_leaf.rs:105-107`) requires `count == 1` for a non-regular file and `stage-5-handoff.md:140-142` says "do not introduce directory or symlink hardlinks". Consequence: an aliased directory in the namespace, an inode value the component's own invariant rejects, and a canonical result the reference cannot produce. Corroborated by `diagnostics/topology.log` (`T2.dir_second_parent=ACCEPTED`, `T2.stat d/e=Ok((2, 2))`, `T3.symlink_second_parent=ACCEPTED`, `T4.same_batch_duplicate=REFUSED`), an uncommitted sibling diagnostic in this evidence directory. Smallest remedy: in `validate.rs`, when `lookup_optional` finds a base record with `kind != RegularFile`, require `previous.namespace_ref_count + added == 1`; add the cross-directory case to `filesystem_topology`.

**F2 (medium, code defect vs written claim). `MAXIMUM_INODE_SERIAL` is enforced only on the root serial.**
Trigger: build or update with a non-root serial such as `i64::MAX + 1` (or `u64::MAX`) in `InodeUpdate.serial`, `new_inodes`, or a directory binding.
Observed: the only range check is `identity.rs:47-52`, reachable only through `FilesystemRoot::new` (`root.rs:50-67`); every other site checks `!= 0` only (`input.rs:156,165`, `format.rs:155,354,401`, `inode_leaf.rs:298`). Expected: the reference rejects `> i64::MAX` on every row (`crates/layerfs-content/src/tree/compact.rs:13-18`, used at `compact.rs:379` for inode leaves and `compact.rs:484` for directory leaves). Consequence: core emits a canonical inode leaf/directory leaf that the reference cannot decode, and `stage-5-report.md:289` ("Inode serial | enforced | 1 .. `i64::MAX`") is an over-claim; the existing boundary diagnostic probes only the constructor (`diagnostics/stage5-diagnostics/src/main.rs:303-311`). Smallest remedy: range-check serials in `FilesystemInput::check` and in the binding loop of `validate::check`.

**F3 (medium, duplication). Two live leaf-page codecs.**
`InodeLeaf::{encode,decode}` (`object/inode_leaf.rs:189,239`) and `CompactInodes::{encode,decode}` (`sorted/format.rs:332,440`) both implement the same framing; only the 73-byte value codec and the constants are shared. `stage-5-handoff.md:109` explicitly forbids duplicating the leaf codec. The two already return different error variants for the same malformation (`TrailingBytes` vs `InvalidRecord("inode leaf length")`), and the sealed golden test covers only `CompactInodes` (`filesystem_codec.rs:56-93`); `InodeLeaf` has only a self-referential round trip (`tests/inode_leaf.rs:41-58`, whose expected width is the product constant). Consequence: the C1 writer and the C2 pooling reader can diverge silently. Smallest remedy: express `InodeLeaf` as a thin wrapper over one shared grammar (or delete it and keep `CompactInodes`), plus one equality test against the sealed 2-row bytes.

**F4 (medium, evidence gap). The "sealed" oracle is regenerated in place by a normal root-workspace test.**
`crates/layerfs-content/tests/stage5_reference_fixtures.rs:619-620` is a plain `#[test]` (no `#[ignore]`) that writes `core/crates/layerfs-content/tests/fixtures/filesystem/manifest.rs` and `*.bin` (`stage5_reference_fixtures.rs:478-480,801,902`) from the *live* reference tree. The bytes it produced are genuinely independent of core and correct today (I hashed and decoded them), but any drift in the reference workspace silently re-blesses them. Consequence: "sealed external bytes" is a process claim that a single `cargo test` can defeat. Smallest remedy: gate the writer behind an explicit env var or `#[ignore]`, and keep a read-only comparator test.

**F5 (medium, evidence gap + acceptance divergence). Old same-version store with the narrower role CHECK opens successfully.**
`sqlite/schema.rs:89-135` validates identity, table/column shape, STRICT, indexes and the policy row, but never the CHECK bodies, so `CHECK (object_role BETWEEN 1 AND 6)` and `...BETWEEN 1 AND 13` are indistinguishable at `user_version = 4`. The report's refusal claim (`stage-5-report.md:46-50`, `completion-report:233-247`) rests on a manual throwaway-SQLite experiment, not a committed test; `diagnostics/run.log` shows `store.open.old_schema=ACCEPTED`. Consequence: a narrow store is usable until the first tree-role write, and no test pins either behaviour. Smallest remedy: commit the reproduction as a `layerfs-storage` test and either document the deferred failure as the contract or add the role range to `schema.rs::validate`.

**F6 (low). Profile constraints are prose, not a schema.** `root.rs:21` declares `scope32;serial8;inode81;leaf50-100;branch64-127;page8192;depth31;directory-fill2/5`; every value matches `limits.rs`/format constants **by my hand check**, but nothing derives or tests the correspondence, and `profile.profile() == profile_id()` (`filesystem_codec.rs:137`) is tautological. `MINIMUM_DIRECTORY_BRANCH_CHILDREN` (`limits.rs:28`) is dead (one occurrence, its own definition); the live checks are literals `2` at `format.rs:190` and `directory/read.rs:262`. Remedy: one test parsing `PROFILE_DESCRIPTION` and asserting the constants, or delete the unused constant.

**F7 (low). Declared page capacity is one row above the ceiling for directory leaves.** `page_items(0) = (8192-44)/11 + 1 = 741` (`format.rs:292-298`) while floor((8179-31)/11) = 740. Only reachable through `encode_directory_page` with a caller-built page; it fails as `ObjectLimitExceeded` at `finish_node` (`format.rs:671-676`) rather than as a partition error. Remedy: use the size-derived bound.

**F8 (low). Negative coverage of role bytes is thin.** Wrong-role refusal is implemented for every record class (root `root.rs:127`, node pages `format.rs:213,436`, symlink `symlink.rs:63`) but only the inode-leaf role byte has a test (`filesystem_codec.rs:202-207`, `tests/inode_leaf.rs:150-155`). Untested: directory leaf/branch role, inode branch role, root role/reserved byte, symlink role/flags, branch `subtree_bytes` mismatch, child-summary mismatch. Remedy: extend `malformed_and_reserved_input_is_rejected_once` over every sealed fixture (the fixtures are already in the manifest).

**F9 (informational). `InodeIdentity::check_scope` is dead** (`identity.rs:64-73`, one occurrence); the scope is enforced once at the root (`validate.rs:53-57`) and never travels with the bare `u64` serials the operation accepts (`input.rs:27,29,49`), which contradicts the module's "every public identity value" comment.
