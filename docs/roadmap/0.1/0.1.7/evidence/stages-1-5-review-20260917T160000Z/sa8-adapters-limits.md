## B. Placement verdicts

**Transport/URL/plugin/network proof:** `grep -rn 'transport|network|socket|TcpStream|UdpSocket|http|Url|endpoint|grpc|protobuf|tonic'` over `core/crates/**/*.rs` returns **10 matches, all prose** in comments/tests (e.g. `storage/tests/persistence_failure.rs:250`); `plugin|registry|inventory::|linkme` returns 4 matches, all in test text. No URL, endpoint, registry, `std::net`, VFS or connection-provider abstraction exists in either crate. Nothing in core can talk to a process boundary today.

**(A) One process, host-only FUSE-style adapter → C1 → C2 → local SQLite — READY TODAY (as public seams) / INCOMPLETE as shipped composition.**
Evidence: the seams are byte/ID-only and locally composable — `construct_stream(policy, capacities, input, &mut SaveHandoff::new(&mut op), scope)` then `op.finish(scope)`, then `Store::read_batch` → provider, exercised in `layerfs-storage/tests/core_pipeline.rs:186-223`; the filesystem route with `FileBacking` + real `Store` + a `StoreReader` provider in `layerfs-storage/tests/filesystem_pipeline.rs` and `examples/measure_filesystem.rs:192-216`. Minimum work (adapter, not core): (1) the product composition that no `src/` file contains (`SaveHandoff` appears in product src only as its definition); (2) `impl AuthenticatedObjects` over `Store::read_batch` (identity is already re-checked in `cas/read.rs:91`); (3) a `FileBacking` directory and a FilesystemRoot publication step; (4) FUSE mapping (paths, errno, permissions, open handles) which core explicitly does not own. Constraints the adapter inherits: one operation is single-thread (`!Send`), one writer per Store, no history retention, reads are per-node point calls so a FUSE read of a deep path costs O(components+levels) provider calls.

**(B) Core (C1+C2+SQLite) moved to another container/host while Workspace/FUSE stays local — moving the whole embedded service: ADAPTER WORK REQUIRED.**
Evidence: no core type reads a mount, a Workspace, a history entity or an endpoint (`lib.rs` doc claims match the grep: no `workspace|history|mount|quota` types in product src); `Store`/`FileBacking` take caller paths, and every cross-seam value is owned bytes + a plain `Result`. Minimum work: a transport at the operation boundary (bounded input, finalized objects, read waves, one `TimingReport`), a thread/process decision because `SaveOperation`/`OrderingBacking`/`TimingScope` are `!Send`, relocation of the run directory and the SQLite file to the service side, and a Workspace-side batcher (C1 emits per-page point reads). Not a core blocker. Distinguish: in this variant **the whole C2 service moves**, so the SQL layer stays local to its own disk.

**(C) C1 and C2 separated by a transport — object-stream variant: ADAPTER WORK REQUIRED; "replace C2's SQL backend with remote SQLite": CORE BLOCKER today.**
Object-stream variant: `FinalizedConsumer`/`AuthenticatedObjects` carry only owned bytes, IDs and role, so a transport that preserves order/cardinality/single-attempt errors satisfies them without core change. Adapter must supply: batch splitting (the trait has no count/byte cap and C1 can hand it an unbounded `lookup_inodes`-shaped batch, `objects.rs:76`, `inode/read.rs:107-114`); no cancellation channel exists, so a cancelled request must drop the operation (`SaveOperation::Drop` = one best-effort cleanup, `store.rs:460-471`); never resend after a lost acknowledgement (only one `StorageError` is retained, `store.rs:508-517`); and it must not attempt to remote the *save operation itself* — `SaveOperation` is `!Send` and owns an open transaction.
Remote-SQL variant, the requirements a provider must meet (all from source): (1) the connection is built from a local `PathBuf` (`store.rs:93,106-143`; `connection.rs:17-26`) — there is no handle/URL seam; (2) `PRAGMA journal_mode=MEMORY` is read back and anything else is refused (`connection.rs:32-36`), plus `synchronous=OFF`, `temp_store=MEMORY`, verified `foreign_keys=ON`, zero busy timeout (`connection.rs:37-44`) — a provider that ignores these fails open (good), but server-side WAL behind a compliant-looking client would silently break the no-WAL rule (UNVERIFIED for any remote provider); (3) writer exclusivity is one `BEGIN IMMEDIATE` attempt (`write.rs:45-49`) re-acquired after every bounded COMMIT (`owner.rs:832-849`) and cross-checked by `W==MAX(pack_id)` (`owner.rs:177-186`) — it must survive transaction boundaries (doc `admission-and-persistence.md:467-472`), which per-transaction serialization cannot give; (4) pack writes are whole-BLOB single statements — `INSERT INTO object_packs(pack_id,data)` / `UPDATE object_packs SET data=?2 WHERE pack_id=?1` re-sends the whole assembled pack per append (`write.rs:70-91`); the ordinary/whole-file/pooled pack cap is 256 KiB and the singleton format width 16 MiB+4096 (`policy.rs:47,75`; reachable ≈1 MiB because a whole-file raw payload is cutoff-bound, `encoding/full.rs:139-214`); (5) there is **no byte-range read**: `SELECT data FROM object_packs WHERE pack_id=?1` (`lookup.rs:151-163`) fetches the entire pack, so "grouped physical reads" means whole-pack transfer, paged locators of 128 ids with up to 129 bound parameters and `prepare_cached` (`lookup.rs:36-85,126-149`); (6) same-operation visibility requires read-your-writes in one session (`owner.rs:308-317`, `store.rs:316-372`); (7) the publication watermark is read and advanced inside the save's final transaction (`sqlite/schema.rs:119-124`, `owner.rs:904-909`) and must be atomic with it; (8) cleanup depends on SQLite FK semantics — `ON DELETE CASCADE` for packs, `ON DELETE NO ACTION` for bases (`sql/schema.sql:42,62-63`; `sqlite/cleanup.rs:48,103,120`); (9) SQLite build/runtime maxima are the **host** library's and are neither set nor checked by the product (`tests/policy_capacity.rs:320-363`; `examples/memory_ledger.rs:428`; the rusqlite `limits` feature is declared in `layerfs-storage/Cargo.toml` but has no call site). Minimum work: a backend seam in C2 replacing path→handle, a provider-level exclusive writer session, whole-pack transfer with declared provider row/BLOB limits, pragma/FK parity evidence, and no-WAL proof. This is a C2 implementation change.
