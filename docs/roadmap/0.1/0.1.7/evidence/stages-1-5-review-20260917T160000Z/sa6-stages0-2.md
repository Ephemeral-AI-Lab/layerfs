## C. Findings (severity ordered)

**A — S2, OPEN (prior review F5, unremediated). The read path is still a point-call loop and every C2 read call re-creates its connection and 1 MiB decode workspace.**
- Location: `layerfs-content/src/file/mapping/read.rs:190` `reader.read_canonical(id)` once per visited mapping page → `object/access.rs:23-35` (point read = one-ID batch) → `layerfs-storage/src/cas/store.rs:205` (fresh connection per `read_batch`) and `:210-212` (`DecompressionWorkspace::new()`), with `encoding/codec.rs:35,389` = 1 MiB decode and `:33,159` = 2 MiB encode workspace per owner acquisition (`cas/owner.rs:190-191`).
- Trigger: any chunked read whose range spans N mapping pages (branch descent, `mapping/read.rs:209-233`).
- Observed vs expected: source shows N provider calls, each opening a connection, applying the pragma profile and allocating 1 MiB; the prior review measured 0.27–0.47 ms fixed cost per point call. Expected (review F5 fix (a)/(b)): one batch call for the overlapping children of a branch and a workspace sized/pooled per provider.
- Consequence: navigation cost is dominated by fixed per-call work and by an unmeasured allocation; the integrated C1/C2 read picture is distorted.
- Smallest remedy: batch the overlapping child ids of one branch into a single `read_canonical_batch`; retain/size the provider's decode workspace instead of allocating per call.
- Evidence status: source-derived; **the prior measurement was not re-run here** (`NOT_RUN`), and no remediation evidence exists for this finding in either remediation directory.

**B — S3, OPEN (prior review F7 residue). Dead public API is still exported and has no caller anywhere in `core/`.**
- `layerfs-content/src/object/id.rs:99` `authenticate` (re-exported `object/mod.rs:19`); `layerfs-content/src/file/mapping/codec.rs:332` `chunk_canonical_len` (re-exported `file/mapping/mod.rs:12`); `layerfs-storage/src/encoding/codec.rs:631` `group_body_parameters`; `layerfs-storage/src/sqlite/lookup.rs:175` `policy`.
- Verified by repo-wide grep over `core/` (`--include=*.rs`): definition plus re-export only.
- Consequence: public surface promises behaviour nothing proves; the F7 estimate (~90–120 prod LOC) is only partly realised.
- Remedy: delete the four items, or use them (e.g. use `chunk_canonical_len` in the chunk encoder instead of its inline arithmetic at `mapping/codec.rs:60-79`).

**C — S3, FAIL (documentation). The Stage-0–2 C2 contract still states a superseded schema identity.**
- `content-storage-policy-and-tables.md:304-310`: "four tables and 19 columns", "**As implemented, the schema has 20 columns and `user_version = 2`**", "`user_version = 1` is rejected".
- Final tree: `sql/schema.sql:10-11` `application_id = 1279677261`, `user_version = 4`; 21 columns across four tables (`sqlite/schema.rs:22-58`); `stages-3-4-final-review.md:378` and `stages-3-4-review-20260917T022248Z.md:33` record the 4/21 state.
- Consequence: a reader of the C2 contract gets the wrong identity and column set; the schema source of truth is `sql/schema.sql`, not the governing doc.
- Remedy: amend those lines (or replace them with a pointer to `sql/schema.sql` + `sqlite/schema.rs::REQUIRED_TABLES`).

**D — S3, INCOMPLETE (frozen-partition criterion). The mapping profile digest duplicates partition constants as literals instead of deriving them.**
- `file/mapping/codec.rs:33-47`: the digest feeds `64_u16` (`= MIN_ENTRIES`, types.rs:13), `128_u16` (`= MAX_ENTRIES`, types.rs:15), `31` (`= MAX_LEVEL`, types.rs:17) and `32_768_u32` (`= cdc::MAXIMUM_CHUNK_BYTES`, gear.rs:17) as literals; only the CDC half is derived, through `cdc::profile_id()` (`:44`).
- Trigger: change any mapping partition constant (e.g. `MIN_ENTRIES 64 → 32`) — `profile_id()` does not change, so file states written under the old partition rule still decode as current, and `tests/object_identity.rs:146-151` still passes because it compares a digest that did not move.
- Expected: a profile identity computed from the constants it freezes.
- Consequence: "frozen" is enforced by review discipline only; a partition change can silently keep the same profile id.
- Remedy: hash `MIN_ENTRIES as u16`, `MAX_ENTRIES as u16`, `MAX_LEVEL`, `cdc::MAXIMUM_CHUNK_BYTES`, `NODE_HEADER_LEN` and the entry widths in `profile_id()`.

**E — S3, OPEN (admission validation gap; no test). C2 does not check a caller-declared tree role against the object's inner tag.**
