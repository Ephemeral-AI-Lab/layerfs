## Explicit application disposal

V2's successful consumer did not establish host disposal. The host preserved
EOF plus macOS NotConnected from its original automatic native shutdown. No
new predicate may turn that original CloseFailed into successful closure.
A fixed sleep or racing a fence against delivery is not the correction.

Reuse existing Supervisor::fence, SupervisorWake/step, original Delivery and
Upstream fence/join ownership. The external two-process diagnostic adds one
bounded explicit lifecycle control, following the existing application test's
ordered receive/delivery/fence/acknowledgment composition:

1. Before either endpoint starts, freeze a unique run identity and a fresh
   control directory/configuration. Seal it as another external input; it has
   no publication, session, Save or kernel-cancellation authority.
2. The consumer retains the original final Binding Message, its correlation,
   exact logical reply bytes/digest and actual context. After its oracle and
   ordinary local Close/Gone, it publishes one complete received-and-ready
   control. It makes no further runtime RPC or socket close before host acknowledgment.
3. The host independently retains the exact successful final Binding Delivery,
   complete original output receipt, typed Binding and same correlation/bytes.
   Only matching original delivery and consumer receipt/control authorize its
   one explicit application fence. No first Binding or guessed latest value qualifies.
4. Host observes the actual joined input/output fence, drops retained original
   results deliberately, checks original zero credits and Save custody, and
   publishes its successful local-disposal acknowledgment. Any failure retains
   its original owner/cause and does not publish a success acknowledgment.
5. Consumer then attempts its own original fence/join under its unchanged5s
   bound. Its real close/partial/reassembly outcome remains mandatory; host
   acknowledgment never substitutes for it.

Control output is create-new, bounded, never overwritten or replayed. A receiver
must wait for explicit complete publication, not parse a partly written file.
Readiness waits are distinct from retrying failed I/O; a failed publication/read,
wrong run/context/correlation/body, timeout or refusal ends the original attempt.
Retain attempted/acknowledged prefixes and first/secondary failures. Control
polling, copies, files and waits are external diagnostic work, not hidden product
service or evidence of resident bounds. It must not pump maintenance.

The new host predicate is explicitly different from the historical peer-EOF
predicate. Require caller-requested fence.failure=None; no pending request,
input events, tail receipts, service cancellations/completions or undelivered
results; actual input.close=Some(Ok(())); and output.close=Some(Err(Quarantined))
as the subsequent pre-I/O refusal from that same one-shot close. Input worker
must join with bare UnexpectedEof after an interrupted idle read, or pre-I/O
Quarantined before another read. Exact record-attempt/complete-encrypted-byte
accounting distinguishes those cases. Both require no partial messages,
reassembly credits or secondary close failure. Output worker must join without
failure or retained results. Any CloseFailed, premature quarantine, partial or
truncated encrypted EOF remains a refusal. No Bridge semantics are weakened.

## Logical input binding across Docker's actual source domains

Retain exact original submitted host ROOT:/work and selected volume:/state,
image, CID, actual process argv/entrypoint, labels, environment and working
directory. Inspect HostConfig.Binds by destination; order is not identity.
Require precisely the declared two mounts/access modes and reject alternate,
additional, overlapping mounts or VolumesFrom. Actual Mounts.Source for /work
must equal its own inspect's Binds source, an opaque absolute Docker-domain
value. Never strip/prepend /host_mnt or infer Darwin/Linux inode equivalence.

Opaque source equality alone is insufficient. Match every original consumer
input observation—executable, assignment, acquisition sidecar, base, replacements,
identity and control configuration—to independently sealed pre-start bytes and
exact canonical guest argv. Those hashes must come from original pre-start
reads, not a later rehash offered as replacement authority. Match the original
consumer output location/record identities through the same declared bind.
For each pre/post probe, record its actual executing source path, bytes and SHA256
against the pre-host sealed source; extra mounts or wrong original bytes refuse.
Native volume/root/database stat equality remains solely within the guest domain.
Capture exact verified ownership and raw inspect state before a later evidence
refusal without claiming that refusal passed.
