# Five capped inherited length-growing SDK replacements

Status: premeasurement specification for the inherited-coverage work in #22.
These are versioned replacements for future capped execution, not edits to the
released 32-case `edit_length_changing` registry. Implementation and measurement
follow this document's committed freeze. They are accounted separately from the
130 new timed IDs and 390 new-family sample slots.

The [testing rules](testing-rules.md#inherited-evidence-and-release-scope) require
all five final files to be exactly **524288000 bytes (500 MiB)**. Their initial
files are shorter deterministic prefixes, never described as exact 500 MiB
inputs. The [released SDK contract](../0.1.2/sdk-only-edit-benchmark-rebuild.md)
and `benchmark/fs-bench-pro/families/edit_length_changing.rs` define their
original operation meanings, payload identities and five-repetition policy.

## Sampling and execution

Collect **five fresh identical-plan baseline repetitions per new ID**, numbered
1 through 5: **25 inherited replacement sample slots**, plus **five independent
verifier receipts**, one per distinct input/edit plan binding its five rows.
Do not reinterpret repetitions 4/5 as v0.1.3 random seeds; no fixture or edit
changes between repetitions. There is one instrumented baseline source arm in
Phase 1. A later directional comparison must independently freeze its matched
source arms and order; no comparison is implied now.

Preserve the relative order obtained by projecting the released 32-ID family's
rotations `0,13,26,7,20` onto these five replaced rows. In the row numbers above:

```text
repetition 1: 1,2,3,4,5
repetition 2: 3,4,5,1,2
repetition 3: 5,1,2,3,4
repetition 4: 2,3,4,5,1
repetition 5: 5,1,2,3,4
```

Seal that exact order before collection. Every repetition starts from an
independent clone of the compatible pristine initialized Store. Four cases
share the 524283904-byte prefix/master; the grow replacement has a separate
524285952-byte prefix/master. The master is validated once per acquisition.
Neither measured outputs nor successful verification states are reusable input.

The measured operation calls the public **singular**
`Client::edit_workspace_file_range` once, followed by one public Commit, Clean
End and post-End Branch visibility query. Real FUSE remains attached, but there
is **no performance Exec, shell, ordinary write, tempfile reconstruction,
materialization or same-file batch call**. Zero extension must remain the Zero
variant at the SDK boundary, not inline zero bytes or a POSIX truncate. Generate
replacement bytes and prepare/clone inputs before the timed call.

Reuse `src/sdk_file_edit.rs::edit_commit_end` and `validate_visibility` where
possible. A compatible host adapter may call the same singular operations with
the same boundaries and prove their observed counts, but must preserve
edit-call, Commit-call, edit+Commit, End, visibility and complete lifecycle
measurements separately. New-family generic scaffolding cannot silently replace
the SDK operation or add a measured subprocess.

Retain the inherited short ceilings: SDK edit and Commit calls at most 2 seconds
each, the stronger edit/Commit/End-region tripwire at 2 seconds, fresh timed
worker at 10 seconds, one selected prefix preparation at 30 seconds and one
500-MiB verifier at 30 seconds. The execution contract's resource ceilings and
60-second cleanup limit also apply. Source/build/image preparation is recorded
separately. A miss is a retained failure, never justification to increase a
limit or shorten the workload. These replacement-only rows cannot establish
released complete-family parity or a new optimization win.

## Independent verification and reporting

Before sampling, qualify both prefix identities, their initialized canonical
file/mapping roots, the Store-scoped Branch root and the exact replacement
plans. Expected final bytes are the independent prefix/splice algebra above;
Zero extends with 4096 logical zeros. Stream expected contents with bounded
scratch. The complete expected path set is the root plus `payload.bin`.

The separate verifier checks all bytes, final length, controlled metadata,
canonical file/mapping structure and object identities, fresh Store reconnect,
real-FUSE reopened contents, unchanged inode equivalence where required by the
SDK contract, exact visible Commit/head and clean End. Bind pristine Store
identity and independent expected final file root; the Store-local inode seed
must not be replaced by a candidate-produced root oracle. Chunk transcripts
and Store census run only in this separate verifier lane. Preserve any actual
failure or timeout and report it against the exact source and plan.

Reports list original ID, replacement ID/version, exact initial/final bytes,
plan/fixture identities, five attempted/completed outcomes, valid sample count,
median/range, phase times, preparation and command wall, and distinct product,
verification, resource, cleanup and custody statuses. Do not pool replacement
rows with oversized originals, relabel released evidence, claim unchanged
32-case admission, or add these 25 samples to the 390 new-family count.

## Minimal implementation interface

After this specification is committed, add only
`families/edit_length_changing_capped.rs` as the canonical pure definition.
Expose `cases() -> Vec<workspace_common::Case>`,
`fixture(&Case, repetition: u8) -> Result<Vec<Entry>>`,
`expected(&Case, repetition: u8, step: usize) -> Result<Vec<Entry>>`,
`sdk_scenario(&Case) -> Result<sdk_edit_common::Scenario>`,
`registry() -> Vec<sdk_edit_common::Scenario>` and `self_check() -> Result<()>`.
The repetition parameter validates `1..=5` but never changes deterministic
contents. `step=0` denotes the initial fixture and `step=1` the sole edit's
expected final state; other steps fail.

The coordinator owns dispatch, sample ledger/order, cache acquisition and SDK
execution. Reuse the canonical Scenario's `ReplacementKind` to create the
public request; the existing inline-only convenience descriptor is insufficient
for the Zero case. The ordinary workload's `apply` route must reject these IDs
rather than implement an alternative mutation. Registry/cardinality reporting
keeps these five IDs separate from the eleven new performance families.
