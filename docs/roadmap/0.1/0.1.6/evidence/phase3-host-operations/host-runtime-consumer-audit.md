# Host runtime consumer audit

Read-only audit for the #124 host-runtime integration; this is a caller inventory, not a completion claim. Product files were not edited. The earlier non-Commit inventory in contract-resolution §5.1 remains applicable.

The smallest cohesive first migration is the **ordinary FUSE Workspace route**, including its SDK, status and End entrypoints together. Construct one HostOverlay/HostOperations/CommitCoordinator owner before projection attachment, share it between local/container adapters and SDK calls, and stop those routes from reading a separate `Workspace.live` mirror. Keeping only a new Commit method beside the old ordinary routes would leave two authorities. Explicit Materialize/reconciliation consumers remain visible migration obligations; they cannot silently fall back to legacy ordinary-Commit freeze while claiming the whole feature complete.

## Specific ownership and lease risks

- `CommitCoordinator::abandon` resolves retained publication before discarding its stage; `Workspace::discard` currently just discards pending_stage and clears spool. Call the coordinator path before owner destruction, including owner Drop and failed attach/End cleanup. Keep receipt cleanup failures observable and retryable.
- `WorkspaceWorker` owns both `workspace.remote` and `worker.remote`; `DockerProjection` additionally owns `Arc<BackingServer>`, whose handler captures the backing/host authority. Clear these only after successful shutdown, and avoid introducing an Arc cycle from HostRuntime back to its worker/server.
- Detached Snapshot/ReadLease/Range owners must retain their backing and aggregate budget after the session record ends. Anonymous arena handles permit this; deleting the runtime directory is not proof all backing is reclaimed. End cannot prematurely drop their ownership permit.
- The branch-lease API exists at `LayerStackStore::acquire_workspace_lease`/`schema::BranchLease`, but a repository-wide Rust search currently finds **no Workspace/Workspaces/CommitCoordinator caller**. Existing lifecycle tests create two Workspaces on one branch and exercise HeadMoved/CAS. Do not accidentally introduce a lifetime-exclusive lease at construction under the assumption it was already present. Preserve Store conditional publication and existing admission ownership; reconcile any new lease wiring with those current semantics.
- The old `head_movement_retains_stage_and_freezes_mutation_until_discard` test contains a freeze expectation superseded by the new contract. Preserve its stage/CAS/explicit-discard assertions while replacing the obsolete ordinary-mutation exclusion assertion with live progress.

## Small targeted integration checks

1. Create ordinary host/container FUSE session, run a held Commit and a real SDK splice/command against the same inode; inspect live bytes, C1 cut, C2 predecessor and unchanged mount/handle identities.
2. Commit a changed session; summary/diff become clean at covered sequence despite nonzero monotonic generation. A later write becomes dirty; Clean End refuses only actual outstanding work.
3. Lose a publication response, then Discard/owner Drop: resolve the exact receipt, preserve published history, remove only the matching retained stage, and verify mount/helper cleanup before releasing ownership.
4. Hold a file ReadLease across session removal and backing reclamation; keep its bytes and budget valid until explicit release/detach.
5. Reconciliation: resolve one conflict, edit unrelated path (choice survives), edit intersecting path or hardlink alias (choice invalidates), preserve private prepared objects, and publish the selected base/head transition through its explicit operation.

No benchmarks, releases, issue updates or product changes were performed by this audit.
