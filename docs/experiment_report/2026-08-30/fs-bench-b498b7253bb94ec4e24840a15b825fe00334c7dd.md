## Benchmark executed

The benchmark exercised the real container FUSE route:

```text
fs-bench process in prepared container
  -> Linux kernel FUSE mount at /workspace
  -> exact-source linux/arm64 layerfs-fuse helper
  -> capability-authenticated ordered proxy
  -> exact-source host Workspace worker
  -> BranchStore plus immutable LayerStackStore parent route
```

Configuration:

```text
MOUNT=/workspace
BASE=/var/tmp
REPS=3
WARMUP=1
RANDOMIZE_TARGETS=1
SCENARIOS=all twelve frozen offline scenarios
host Workspace/Store profile=release
```

Before timing, one prepared container mounted Reference and Replica
simultaneously and verified real reads, writes, hard links, symlinks, Commit,
and clean End. The benchmark then created a fresh Workspace for each placement.
Every sample used a fresh target. Pure-read, pure-copy, and overwrite source
data were prepared outside the timed region.

## Anti-hardcoding interpretation

Production code contains no condition on benchmark scenario names, the
1,000-file count, the 64 MiB size, or `/var/tmp`. The relevant hot-path behavior
is general: cached complete-directory views, ordered reserved creation, FIFO
fsync acknowledgement, normal kernel page cache, and canonical sparse-zero
handling. Zero-filled large-file rows benefit from sparse-zero behavior, so the
numbers must not be relabeled as high-entropy storage throughput.
