## Hypothesis and implementation

Accepted M0 spent a median 454,577,666 ns in reconstruction and issued 5,371 reconstruction SQL preparations/statements, one per authenticated object. The hypothesis was that SQLite call/setup overhead was material and could be reduced without weakening authentication by fetching each file leaf's at-most-K chunk objects in one ordered query.

The accepted implementation is deliberately narrow:

- the existing file walker gained one reconstruction-only switch; scrub, pre-COMMIT closure validation, and range reads retain their accepted-M0 paths and timer boundaries;
- one private `Store::for_each_leaf_bytes` query builds an ordinal `VALUES` relation for one decoded leaf, `LEFT JOIN`s the authoritative `wp4m_objects` table, and orders by ordinal;
- the helper refuses more than profile K references, validates every returned ordinal, reports a missing joined row as `MissingObject`, authenticates every canonical BLOB against its `ObjectId`, and the shared consume callback authenticates every decoded raw payload against its `ChunkId`;
- rows are consumed incrementally, so duplicates retain separate ordinals and output order while only one canonical BLOB is materialized at a time;
- exact batch-query, reference, maximum batch, generated-query-buffer, SQL, authentication, and Q counters were added.

No dependency, schema, database, WAL mode, worker/pool, cache/map, source staging, append/pack, identity, receipt, publication boundary, or COMMIT count changed. The prior rejected M1 borrowed-row work remained reverted.

## Big-O and bounded memory

The authoritative work still authenticates Θ(total canonical bytes + references), and for fixed K the total time class remains Θ(references + bytes). M2 is therefore **not** an asymptotic total-time claim. It is a structural reduction in reconstruction database round trips: 5,371 individual object statements become 83 bounded leaf queries plus 87 existing non-leaf/object queries.

Additional semantic memory is O(K + largest authenticated canonical BLOB), with K=64 here; no unbounded cache or map exists. A leaf's request, ordinal validation, and output are streaming and preserve duplicates. Other heap-copy volume, SQLite page-cache/statement memory, fsync observations, query plans, peak journal/temp bytes, process/host physical I/O, and file height remain explicitly **Unavailable**.

## Verdict

**PASS.** Correctness and identity passed; both timer equations reconciled in every row; exact intended batch, authentication, SQL, BLOB, Q, topology, and one-COMMIT counters passed; protected capture/lifecycle/CPU/RSS/storage guards passed; and reconstruction improved 7.169% with 5/5 paired wins. M2 is accepted for M3. No qualification, profile-selection, promotion, or asymptotic-performance claim is made.
