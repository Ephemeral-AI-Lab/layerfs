## Hypothesis and implementation

The previous row exposed correct end-to-end timers but collapsed work counters across phase boundaries, counted only a subset of hashes, could not state row-to-`Vec` copy volume, and reported logical Q as `Unavailable`. The smallest root-cause fix was to instrument the existing shared `Metrics`, `Store`, canonical-ID, raw-chunk-ID, mapping walker, scrub, reconstruction, range, reopen, and publication paths in the private candidate executable. No schema, DB, WAL mode, worker, pool, cache, source staging, codec, walker, identity, publication boundary, or production engine was added or changed.

The implementation adds:

- exact before/after per-phase metric snapshots;
- disjoint identity hashing counters for raw bytes, canonical ObjectId construction, and fetched canonical authentication;
- canonical bytes authenticated/written, object created/reused/authenticated, SQL invocation/row, row-BLOB read/write/copy, incremental-BLOB API, COMMIT, references/pages/branches, W/D, and storage counters;
- an exact logical-Q equation using the frozen 33,604,696-byte ordinary window contract plus the maximum explicitly live semantic charge;
- measured reopen SQL/row/BLOB accounting and DB/sidecar logical, apparent, and allocated snapshots;
- explicit `Observed`/`Unavailable` status. No unavailable value is serialized as zero.

`sql_preparations` means Rust `prepare_cached` invocations/cache lookups, not SQLite cache misses. `row_blob_copy_bytes` counts bytes materialized by measured SQLite row-to-`Vec<u8>` reads. Other allocator-level copies remain `Unavailable`.
