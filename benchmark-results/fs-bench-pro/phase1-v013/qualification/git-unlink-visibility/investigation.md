# Acknowledged unlink visibility defect

Original failing attempt: `git-tool-10-s1-performance-5abd0cdea1ba`, source `b8c2ad4bf4fa0415fd49d57abea15729b33a4284`. [Decoded workload stderr](decoded-workload-stderr.txt) is the concatenation, in recorded order, of the exact `OutputChunk.bytes` arrays in original stderr. It reports 10 completed targets, 3 acknowledged unlinks, a successful first Git status, and then `git diff --no-ext-diff --binary --` failing to stat `tracked/delete-318.dat` with ENOENT. It fails before Commit. Original stderr SHA-256: `fd8c01bfcc93d155f21e93d7a9c8006ba57d5b8a57a205e238eaee3ff6609ecd`.

`ProxyClient::unlink` acknowledged a regular-file deletion by queueing it in `pending_unlinks`. It removed the name from a cached directory when one existed. With no complete cached parent directory, the following `lookup` passed through to the host, because `cached_lookup` had no directory and `exchange_at` flushed writes rather than pending unlinks. The host still returned the old binding until an unrelated barrier processed deletion. Thus successful unlink could be followed by a successful lookup of the removed name.

A socket-level public-port regression reproduces that product defect deterministically without Git, FUSE mounting, workload inputs, or benchmark measurement. `reproduced/output.log` records the failure: lookup after acknowledged unlink returns the old Attr instead of NotFound. `before/output.log` separately preserves the initial test compilation error (Request lacked Debug); it is not product-failure evidence.

The fix changes only `ProxyClient::unlink`: reuse its existing cache lock to observe whether the parent directory is cached; queue the regular-file deletion as before; if the parent is uncached, complete the existing barrier before acknowledging it. Complete cached parents retain the existing deferred batch and authoritative negative lookup. No lookup/read method, cache representation, memory layout, protocol, capacity, or workload changes. `corrected/output.log` records one passing regression covering both uncached-parent host visibility and cached-parent retained batching. Final source SHA-256: `5e136f4ba3e7d9ea2c84778440753aa952b02259d643b7179fb2e697e036ffe5`.

This proves and repairs the underlying visibility defect. A corrected real Git run remains necessary to confirm recovery of the reported Git case; this unit receipt is not substituted for that execution or its final independent verification.
