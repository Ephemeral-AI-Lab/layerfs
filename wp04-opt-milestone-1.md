## Hypothesis and implementation

M0 measured 316,050,101 bytes of SQLite row-BLOB materialization into `Vec<u8>` across the lifecycle. The hypothesis was that inspecting raw chunk objects directly through rusqlite's borrowed `Row::get_ref(...).as_blob()` lifetime would materially reduce scrub, reconstruction, and range time while preserving authentication and bounded memory.

The attempted change was deliberately small:

- one private `Store::with_borrowed_bytes` callback, using the existing prepared `SELECT`, authenticating the canonical BLOB before the callback, preserving `QueryReturnedNoRows` and canonical typed errors;
- the existing scrub, reconstruction/pre-COMMIT stream, and range raw-chunk paths routed through that helper;
- the shared mapping decoder returned its already-borrowed payload slice instead of performing a final `.to_vec()`;
- exact per-phase borrowed-row read/byte counters were added.

No dependency, schema, DB, WAL mode, worker/pool, cache/map, source staging, identity, publication boundary, or timer boundary changed. No incremental SQLite BLOB handle was added because the native borrowed row value already provided the smaller bounded solution.
