## Predeclared hypothesis, implementation, and hard gate

For an exact same-count edit, the accepted M3 path rebuilt only the changed file-mapping spine but then authenticated and replayed the entire new file closure before COMMIT. M4 tests the controlling receipt rule directly: authenticate the prior and replacement namespace/file changed spines; compare ordered strong-edge IDs and exact summaries; treat equal child IDs as covered by the exact authenticated prior receipt; and fully traverse every new or different child before publication.

The implementation changes only the same-middle pre-COMMIT closure path. It uses the existing canonical decoders, SQLite borrowed-row helper, typed errors, COW walker shape, transition/root checks, publication transaction, lost-ack reconciliation, fresh full scrub, bounded M2 reconstruction, and range verification. It adds no schema, database, WAL, worker/pool, cache/map, source staging, append/pack, identity, or COMMIT change. Full create, +1, full-replace, and directory paths retain full pre-COMMIT traversal. The sequential full closure digest is still derived after fresh reconstruction, where that complete traversal already existed; no measured work crosses a timer boundary.

The predeclared affected metric is `precommit_closure_validation_wall_ns`, with unchanged timer boundaries. PASS requires correctness and identity, exact timer/counter/Q equations, the intended receipt/spine counters, at least 5% median improvement, and at least 4/5 contemporaneous balanced-pair wins. Durable capture, complete lifecycle, CPU, RSS, physical/allocated storage, every other disjoint phase, and one-COMMIT publication are protected non-regression evidence. Asymptotically, same-count pre-COMMIT qualification should become changed-path-local `O(log_F(N/K))` plus complete traversal of genuinely new/different subtrees, with bounded active-stack memory; +1 remains the unchanged bounded-spool `Theta(suffix)` path and receives no logarithmic claim.

## Big-O, retention, and verdict

The rejected candidate demonstrated a genuine algorithmic change for same-count pre-COMMIT qualification: from full-closure `Theta(N)` authentication to `O(log_F(N/K) + newly divergent subtree)` work for the measured one-chunk edit, with `O(active changed spine + K)` live semantic memory. This asymptotic result is separate from its measured latency. +1 remains the unchanged bounded-spool `Theta(suffix)` path, and no logarithmic +1 claim is made.

**REJECTED.** Semantic correctness, identity, the intended changed-spine mechanism, exact Q/counter/timer equations, affected-metric magnitude, 5/5 wins, one-COMMIT publication, CPU, wall latency, and physical storage all passed. However, external maximum-RSS median regressed 7.921%, beyond the controlling 5% protected-resource limit; peak memory footprint regressed 11.872%. The frozen five rows are not replaced or averaged with post-hoc diagnostics. M4 implementation work is therefore reverted in isolation, while its benchmark and algorithmic evidence remain recorded. The retained implementation state returns to accepted M3.

`qualification=false`, `promotion=false`, and `rejection=false` remain unchanged. This verdict rejects only the M4 implementation milestone; it is not a profile rejection, selection, or promotion claim.
