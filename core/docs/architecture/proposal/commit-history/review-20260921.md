# Pair 2 implementation specification — pre-publication audit

> **Status:** Research; informative and not a product contract.

Reviewed artifact: [implementation specification](implementation.md).
Design parent: [#180](https://github.com/Ephemeral-AI-Lab/layerfs/issues/180).
Source basis: `a02168adbb1b02571941654919cefca12dbc1f42`, with landed
multi-writer C2; reference tag `v0.1.6` at
`44cf748486863ab7c21ca47e731bd88e2b9a7b4a`.

The user requested independent subagent review before creating the implementation
issue. Three read-only reviewers audited different boundaries, then reviewed the
concrete specification. The parent author reconciled findings before publication.
This is a design audit, not evidence that C5 is built, tested or qualified.

## Findings and dispositions

| ID | Finding | Disposition in final spec |
| --- | --- | --- |
| R01 | Old schema-6/single-save assumptions were stale. | Pin landed schema 7/six tables, W=2 service and private saves. Keep C2 ownership/publication internal. |
| R02 | A root's presence/hash is insufficient typed filesystem provenance; current service can accept wrong-role metadata roots. | Require bounded semantic-role validation or unchanged trusted base metadata; reject wrong-role stored roots; no hidden whole-tree scan in C5. |
| R03 | Fixture-only initialization would leave pair 2 dependent on absent Workspace/new-inode routes. | Include real Empty/bounded logical-manifest bootstrap, fresh service-assigned identities, metadata/symlink construction and sequential prerequisite saves. State 128-entry/32 KiB limits; defer general host import/live create explicitly. |
| R04 | New opcodes overflow the existing u8 grant mapping and accidentally classify every opcode >=3 as a content mutation. | Group query/command as opcodes6/7, history profile2, preserve legacy mask31, use checked grants/exhaustive classification and separate metadata-only dispatch. |
| R05 | Request enums alone omit response matching, failure decoding and daemon delivery work. | Include all codec/validation/client matching work; reuse the daemon relay with an external driver. |
| R06 | Live-process root maps or Workspace-only expected context would defeat independent history. | Self-contained frozen stages and exact tokens; save-to-stage composition in one invocation; fresh connection tests with same continuing authority. |
| R07 | Holding a catalog transaction across construction/save would serialize the multi-writer content path. | Short immediate-admission C5 transactions only; release metadata ownership before C1/C2; no nested C2/C5 locks. |
| R08 | Root-only stage inputs could build from another same-scope root and still CAS a Branch. | Initial profile requires construction base = captured Branch root and intended Commit base = captured Branch base; check before work and in accepted frozen context. No implicit rebase. |
| R09 | Fork base, exact-source UpToDate precedence and no-change multiplicity needed precise definitions. | Selected historical Commit supplies fork base; already-published source checked before stale-base refusal; multiple no-change stages may succeed. |
| R10 | Important reference schema constraints were only implied. | Explicit genesis/child/source uniqueness, same-stack ownership, head/base consistency, null provenance and immutable-field comparison. |
| R11 | MEMORY/OFF cannot prove exposed-reservation continuity after arbitrary restart. | Fresh writable catalog must be created in its owning service process; one continuing authority writes; ordinary reopen is read-only and mutations fail ContinuityUnavailable. No fake clean flag/root-scan proof. |
| R12 | Scope changes were incorrectly described as preserving canonical identity. | Correct H12: metadata-only transitions do not re-encode/select delta bases; scope/profile mismatches are refused. Scope is in filesystem-root canonical bytes. |
| R13 | B publishing an identical ObjectId could be mistaken for A's successful save. | Add H08 case: root equality cannot upgrade A's failed/unknown finish into acknowledged staging. |
| R14 | Delayed metadata input does not prove a prepared-update save has begun. | Require observed C2 ownership overlap for reverse-completion claims; preserve NOT_RUN when the schedule is not established; no product test hooks or sleeps as evidence. |
| R15 | Live head movement was ambiguously called a stale listing cursor. | Immutable anchored cursor remains valid as head advances; reject invalid incarnation/anchor/context, not ordinary head growth. |
| R16 | Earlier LOC estimate omitted bootstrap/trust/protocol work. | Revised central production allocation 4,055; planning range 3,500–5,000; external tests 1,800–3,000 excluded. |

All three reviewers re-read the corrected specification and complete issue draft
and approved publication with no remaining design blockers. Their final pass
verified the named corrections, including base binding, identity/failure handling,
cursor stability and the H04 observation rule. The final wording preserves the
namespace-init worker exception. Implementation acceptance remains open.

## Explicit remaining implementation decisions

M0 must freeze exact catalog application ID/DDL, ID fixtures, wire/result tags,
checked permission mapping, manifest grammar, cursor format/validation and live
authority lifecycle before production code depends on them. These are finite
implementation decisions listed in the spec, not claims of implemented behavior.
The native writable-restart limitation is selected and documented rather than
hidden behind a future proof. The H04 observation gap must remain visible if its
exact schedule is not demonstrated.

All runtime, portability, resource and performance acceptance cells are NOT_RUN
for this documentation work. No source or benchmark changes were made by the
reviewers. Documentation links/anchors, format/whitespace, source references,
table/LOC arithmetic and the existing boundary-guard checks are validated by the
author before committing the documentation; exact results are reported in the PR.
