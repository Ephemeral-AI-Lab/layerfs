# R1b navigation cursor freeze

Status: prospective source freeze, 2026-10-01; parent 53b6bf741. No checks or performance measurements run. This implements the navigation proposal in R1D-PAGED-ALGORITHMS.md only; paged drafts remain separate. SC-01/02/04/06/07/08 apply.

The actual public read_range and ascending RangeCursor use the same private structural cursor. It retains at most MAX_LEVEL+1=32 branch frames, each containing one codec-checked <=128-descriptor Vec, an advancing child ordinal, absolute origin and child level. Initial frame storage is fallibly reserved before provider effects. Every retained decoded descriptor/extent owner checks actual Vec capacity <=128 before retention. The cursor's metadata bound uses compiled std::mem::size_of, never encoded width as allocator evidence: 32*size_of::<Frame>() + 32*128*size_of::<ChildDescriptor>() + 128*size_of::<ExtentSlice>() + size_of::<Navigation>() + 32*size_of::<Frontier>(). Frame Vec and descriptor Vec requested capacities are checked; allocator bookkeeping/native allocations are separate qualifications. A fixed32-demand navigation array avoids another population allocation.

Range pruning advances descriptors whose absolute end <=range.start and leaves the first descriptor whose origin >=range.end unconsumed. Selected branches are acquired as singleton calls through the existing independent-owner page helper; selected leaves are collected across branch boundaries in <=32-item grouped waves. Each frame progresses monotonically and each selected branch is discovered once for the cursor lifetime. One decoded partially served leaf, next extent ordinal and absolute extent start are retained across segment ends so a later ascending segment does not restart the root or reacquire that leaf after cache eviction. Empty segments issue no provider calls. A new independent read owns a fresh cursor. No SQL/scratch is introduced.

Cold full-walk provider calls are B singleton branch calls plus ceil(L/32) leaf calls; nodes_read=B+L. Cache hits reduce actual acquisitions. This replaces branch-level batching, not leaf/payload grouping. The existing two-level count test remains valid because B=1 there. For sparse/segmented reads, grouping follows each call's needed leaves and exact pruning; branches/current partial leaf already discovered are not reacquired. Canonical root/nonroot contexts, per-node logical/extents summary checks, checked absolute rebasing, output order and payload32 grouping remain unchanged. Root leaf uses root context. Navigation cache64 and admitted smaller caches retain existing meanings and ownership.

Simultaneous ownership includes the retained path, optional partial leaf, discovery/decoded branch transient, fixed frontier array, current <=32 canonical page owners, cache64 copies, existing <=32-object payload wave and ordered demands, provider returned vectors and sink/caller allocations. Reuse the delivered page helper's validation-before-retention and independent current owners. This is a first-party requested-capacity bound, not global ReadWindowPermit, native heap, RSS or physical-provider containment proof.

Any provider/codec/sink error terminalizes RangeCursor; later calls refuse without another provider effect. Partial output before a later failure remains owned by the sink and no error is converted to success. No retry, root restart or alternative traversal. Successful segments advance the declared endpoint; failed segments retain terminal state. Per-call byte coverage must equal the requested interval.

Expected tests are pinned independently: existing cache_oracle::wide v1 framing supplies65 full leaves and repeated payload slices. Full reads require66 mapping acquisitions and4 navigation calls with max32; cache1 ascending overlapping-leaf/gapped segments acquire the root once and each needed leaf once; boundary outputs are independent expected byte slices. In-memory tests retain that provider label. Existing real StoreProvider mapping_cache and deep file_read bodies plus owning content/storage checks are required at root's serialized frozen check checkpoint, not run by this worker. The new level2 test independently frames two64-child branches and a two-child root over the existing leaf bytes; expected concatenation and nonzero-origin range slices precede candidate reads. Larger/deeper arbitrary source claims require their own independent expected framing. Draft, native engine/physical and speed qualification remain open.
