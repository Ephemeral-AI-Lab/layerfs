# #243 ordinary Workspace shell scenario v1 — frozen selection

**Prospective contract.** This document, `core/benchmark/fs-bench-pro/registry/workspace-shell-package-v1.json`, `shell_package.py`, `benchmark_shell.rs`, and `verify_shell.rs` are committed before any live package attempt. The case commands are the exact UTF-8 strings in the registry, passed unchanged to one public `WorkspaceApi::exec`. The fixture bytes are the exact recipe in `shell_package.py` and the companion [test-workspace specification](TEST_WORKSPACE_AND_COMMANDS.md). A pre-run preparation receipt seals the actual fixture manifests, binaries, image, Store masters, and source identity. The runner refuses a dirty or changed source. A change to any of these inputs creates a new scenario version or a newly committed contract; an old attempt is never overwritten or re-labelled.

## Operation and prepared state

The registered family is `workspace_shell_package`, version 1, operation contract `workspace-api-exec-posix-fuse-package-v1`. The operation surface is the mounted Workspace POSIX/FUSE filesystem. The host Rust SDK example orchestrates the public Project/Branch/Sandbox/Workspace lifecycle. `/bin/sh -c` inside the Linux sandbox performs mutation with `dd`, `cp`, `mkdir`, `rm`, and `mv`. The acknowledgment boundary is one explicit public `WorkspaceApi::commit` after a confirmed zero Exec exit. The failure case requires a definite nonzero Exec exit and **zero Commit calls**. No ioctl, LayerFS editor, shell-text classifier, or alternate mutation path is accepted.

The fixture recipe creates the nine-file version-1 three-package tree. The image has eight immutable version-2 files: seven package and lockfile replacements plus `patch-4k.bin`. The separate 10 MiB and 64 KiB focused prepared trees each add one file. `benchmark_init` initializes each Store/History pair through the public SDK; `benchmark_shell seed` creates its Branch and one old Commit outside the timed attempt. The seed writes the existing `1` byte back to `core/BUILD_ID`, preserving the declared version-1 bytes. The independent verifier checks every path, mode, length and SHA-256 before the masters are closed. Each attempt receives an independent writable `shutil.copyfile` byte copy of its matching validated master. The copy method and hashes are recorded. The master is never mutated by a sample.

| Order | Case ID | Declared operation | Complete command limit |
| ---: | --- | --- | ---: |
| 1 | `mixed-refresh-v1` | Three-package update with overwrite, create, remove, temp-file rename, and lockfile replace | 25 s declared exception |
| 2 | `overwrite-4k-v1` | One 4 KiB positional overwrite in a 10 MiB file | 15 s |
| 3 | `repeated-one-byte-v1` | Sixteen shell-driven positional writes into one 64 KiB file | 15 s |
| 4 | `failed-command-no-commit-v1` | Private overwrite followed by `false`, no Commit | 15 s |

The independent verifier limit is **9 s**. The mixed case alone uses the allowed 25 s complete-command exception. No limit or command is adjusted after an attempt. Construction uses one worker in the existing product default and `LAYERFS_CONSTRUCTION_WORKERS=1` in every child. This selection is four diagnostic baseline attempts, one each, and does not amend the parent #232 56-shape gate.

## Route, oracle, and observation

The driver reports one Exec duration, one Commit duration when called, the full operation duration, cleanup duration, Status projection counters, accepted range bytes, and raw LFT1 events. The runner retains raw stdout/stderr, `LFS_PIECE_COUNT`, `LFS_PIECE_PAGES`, `LFS_FINISH_SUBSTEP`, and any failure diagnostics. Status `write` aggregates namespace mutations; its lower bound is a route sanity check, **not** a FUSE WRITE callback count. Exact WRITE/SETATTR/CREATE/MKDIR/RENAME/UNLINK counts are unavailable unless a separate operation-specific trace is introduced. Retained LFT1 CPU and RSS are process-shared sampled host-driver observations. A short phase with fewer than two resource samples has CPU marked unavailable. These are neither phase-isolated nor container-wide RSS or CPU. Save-wide finish substeps may overlap and are not added together or attributed to the final drain without a matching batch identity.

The source tree has no active range-ioctl dispatcher. A former STATE request on a mounted descriptor must return `ENOTTY` in the Linux mounted regression. Both historical Status range slots and accepted range-payload bytes must be zero in the new samples; the fixed slots remain for reader compatibility and are not inferred to be actual syscall trace counts. The independent read-only `verify_shell` example reopens the published Store and History, checks the Branch head and old Commit, traverses the full old and new trees, rejects extra and missing paths, and checks every file's portable mode, byte count, and SHA-256. The failure case checks that the head still names the old Commit and the old root remains intact. Verifier time is outside the product and complete-command timers.

The host Store copy and Linux FUSE backing cache, including Edit-written bytes read during Commit, are **uncontrolled**. No input is primed, no cache invalidation is asserted, and no raw latency is a cold-cache PASS. Every otherwise correct row is `INELIGIBLE` for numeric performance admission. No numerical speedup target or RSS hard gate is set for this exploratory baseline; raw wall, available sampled CPU/RSS, product limits, and cleanup are reported with their exact scopes. A functional or cleanup failure is `FAIL` even though latency is cache-ineligible. A case never attempted is `NOT_RUN` with a reason. All four IDs remain in the campaign report.

## Custody and execution

Run `python3 core/benchmark/fs-bench-pro/shell_package.py self-check` before preparation. Once this contract commit is clean, use `prepare --output <fresh worktree-local benchmark-results/fs-bench-pro path>`. It builds locked release SDK driver, verifier, and ARMv8 daemon, archives immutable binary copies by SHA-256, creates the image **without** `layerfs-edit-tool`, seals the actual image ID, fixture files/manifests, Core Cargo lock/config and source/harness seals, and prepares/validates the three closed masters. Retain `prepared.json`, build logs, seed receipts, and manifests. Then use `run --prepared <prepared.json> --output <fresh path>` once. Every case gets a fresh cloned Store/History, exact command/spec, raw driver and verifier output, receipt, and SHA256SUMS. The report preserves `PASS`, `FAIL`, `INELIGIBLE`, `NOT_RUN`, timeout, verifier, cleanup, callback/count, LFT1, and full-command results. No unchanged arm is resampled. After collection, only a read-only report is derived from retained files.

Historical v2/v3 registries, tools, reports, and raw receipts remain opt-in archives. Their ioctl numbers cannot support this operation's claim. #232's 56 ordinary-shell shapes stay open until a separately committed amendment selects their actual commands and oracles.
