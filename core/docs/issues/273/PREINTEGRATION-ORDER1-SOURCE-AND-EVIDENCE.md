## 2. Implemented architecture and ownership at the hot/Commit boundary

### 2.1 Public acknowledgement: one selected active revision

The [source description](../../architecture/proposal/fuse-workspace-snapshot-overlay/60-active-backing.md)
and [specification](PHASE4.5-IMPLEMENTATION-SPEC.md) distinguish the cold
indexed splice from eligible monotone tiny-WRITE publication. The Workspace
owns one incarnation-scoped pooled index, a shared authenticated pack tail,
HotDirectory and charged inode cursors. It does **not** introduce a canonical
C1/C2 format or a per-tiny-file root. Each acknowledged WRITE selects one
complete new root/directory/pack revision, then performs checked projection
notification before the accepted-byte reply; a failed candidate is not
silently replayed down a different route. The ordinary mutation gate remains.

```text
one public WorkspaceApi::exec -> mounted POSIX pwrite / WRITE
                             |
                             v
                  FUSE -> coherence / mutation permit
                             |
                             v
            validate held handle, inode, generation, revision
                             |
                      +------+-------------------+
                      | eligible 1..128 B       | otherwise
                      v                         v
          charged HotCursor            generic v2 indexed splice
       EOF / advancing Base/Zero       overlap / Payload / other mutations
                      |                         |
                      +-----------+-------------+
                                  v
                   stage pack + affected I/E/P/R keys
                     (+ first D, L/namespace if affected)
                                  |
                  verified 4 KiB candidate pages + ownership
                                  |
                       select ONE ActiveView revision
                                  |
              checked notification / published-outcome custody
                                  |
                     FUSE accepted-byte reply
```

Here `I` is inode, `D` is generation-dirty, `E` is extents, `P` is a
logical-pack physical locator and `R` its inverse reference; `L` covers
large Payload inverse references. The names and values are specified in the
[v1 format record with its v2 amendment](ACTIVE-FORMAT-AND-EVALUATION-v1.md)
and the v2 specification. A same-inode resident cursor keeps exact
partition/fence/ancestor bindings; other inodes can share the reached index
page without forcing an unsafe stale binding. Ineligible work pays the
actual generic cost rather than masquerading as hot.

### 2.2 Why the selected directory and epochs matter

A private index v2 branch carries exclusive partition fences and a 17-byte
child target (`Cold(page ID, epoch)` or `Hot(slot, reuse epoch)`). Replacing
one leaf through a still-valid Hot target does not rewrite unrelated ancestor
fences. The selected `LFSAHOT2` directory maps 64 slots to authenticated
physical page versions; it is selected *with* the root, not a global mutable
cache. A frozen view resolves **its** directory, including its old slot epoch,
never the live directory's newer occupant. Index pages are 4,096 bytes;
pack pages keep the version-1 `LFSAPAK1` record grammar. New attachments use
v2; old private v1 incarnations are not migrated/adopted.

```text
                    G1 captured ActiveView           G2 live ActiveView
                  +-----------------------+       +-----------------------+
root/height  ---->| root / selected D1    |       | root' / selected D2   |
                  | pack watermark P1     |       | pack watermark P2     |
                  +-----+------------+----+       +-----+-------------+---+
                        |            |                  |             |
                 Cold(id,epoch)  Hot(slot=6,e=4)  Cold(...)   Hot(slot=6,e=8)
                        |            |                  |             |
                 physical page   D1[6] -> OLD      physical page D2[6] -> NEW
                                         |                              |
                               pinned old bytes              current new bytes

                    slot reuse NEVER changes what G1 reads
```

`HotCursor` admits at most eight frontiers; there are 64 selected hot slots
and a 1 MiB current hot reservation ceiling. These are **not** total heap,
RSS, quota, or constant-RAM Commit bounds. Pack writes/verified readbacks,
page registry, selected old versions, physical unlink/refund and ordinary
carries still cost work. Cached authenticated facts cannot be fabricated by
warming a timed path.

### 2.3 Capture, live successor and custody

Capture pins G1's *complete* view (root, selected directory and pack
watermark), seals its tail and advances G2 without stopping a running process.
SaveFile/C1/C5 read frozen G1 while G2 can edit. C5 prepares changed G1 rows
and saved facts away from the state gate, then rechecks live inode revisions
under the gate; only captured changes are installed, preserving intervening
G2 extents, handles and aliases. The 8 MiB default Budget still charges
current/scratch/old+new capacity and can atomically refuse. A known remote C1
Commit followed by local C5 failure **remains owned**, is not retried as an
unknown/failed canonical outcome, and must not reset the backing.

```text
     running process / same held fd, inode
         |     before capture   G1: ... B C
         |     after capture    G2: ... D E F
         v
   live ActiveView ---- Capture pins G1 --------------------> SaveFile -> C1
         |                 |                                      |
         |                 +--> old reader sees G1: ... B C       |
         +--> G2 WRITE D/E while C1 is working                   |
         +--> G2 WRITE F after result                             v
         |                                                  C5 reconcile
         +----------------- recheck revision, preserve G2 <-----+
                                    |
                            release G1's final pin
                                    |
                     verified unlink -> exact refund; failures
                          retain charged custody, not 0 B
```

The phase-4.5 functional proof includes same PID/fd/inode mounted continuity,
old G1 and live G2 byte oracles, selectable old-directory/slot epochs,
quotas, Budget refusal and physical-identity cleanup fault. It does **not**
prove that a later #264 ancestor rewrite preserves those properties. See the
[phase log §4.5.4/5](PHASE4.5-LOG.md)
for the 17/42 coverage and historical failed attempts.

## 3. Complexity: specify variables, work charged, and exceptions

Let `W` be acknowledged WRITEs, `H` selected index height (supported v2
height at most eight), `B` positive bounded leaf/branch spare-space fanout,
`A` physical versions allocated over time, `V` registry entries, `G` retained
selecting pins, `J` retired owners, `E_f` final extents of one saved file,
`D` dirty identities, `P` logical source packs, `K` references/window and
`L` actual SaveFile pack loads. These names are **symbolic input quantities**,
not fitted elapsed-time coefficients. The [spec §9](PHASE4.5-IMPLEMENTATION-SPEC.md#91-structural-amortization)
and [scaling analysis](PROSPECTIVE-SCALING-DECISION.md)
state the conditional proof and remaining costs.

```text
 eligible, monotone frontier only             all other / boundary work
 ----------------------------------            -------------------------
 W ordinary structural edits                    initial admission and first D
 + W/B leaf carries                             split/root-height transitions
 + W/B^2 parent carries ...                     forced slot eviction/normalization
 = O(W) amortized structural updates            general overlap / large Payload
                                                registry, physical I/O, release

 NOT an O(1) public WRITE, O(1) CPU, O(1) RAM, or elapsed-time theorem.
```

| Boundary | Source-derived bound / measured count | Necessary qualification |
| --- | --- | --- |
| Stable eligible hot frontier | `O(W)` total *structural index operations* with byte-balanced carries; ordinary noncarry changes bounded leaf and directory selections. | Only while authenticated frontier/slot/byte capacity stays admitted. First binding, carry, pressure and eviction are explicit work. Finite 3 x 3 cases do not prove arbitrary `W`. |
| One ordinary active candidate | At most 6 or 7 new active files in the restricted ordinary cases, plus 4 KiB page framing/readback and `O(log A + log V + log G)` ownership/registry terms. | Physical allocation/unlink latency is not a constant-CPU promise; no hard kernel-I/O deadline follows. |
| Generic overlap | Work proportional to actually reached `E/R/L` changes, tree height, compaction and publication. | Repeated-overwrite row is **not** a proof all generic workloads have the hot bound. Avoid counting nested directory pages twice as extra physical files. |
| Final-pin retirement | An owner may move through selecting cohorts; conservative `O(J*G*log G)` total plus checked unlink/refund. | An ordinary WRITE should not sweep unrelated retirees; known/unknown failed release stays charged. |
| SaveFile source | Charged `O(E_f)` extent and descriptor state, bounded `K <= 1,024` references and <=32 KiB grouped output, with `L` authenticated pack loads. | `L <= E_f` for relevant packed refs; interleaving can reload packs across windows. `O(E_f)` scratch **is not constant RAM**. |
| G1 -> C5 | Charged prepared patch/map/index scratch plus affected-index installation under the gate; old/new allocations overlap until proven transferable. | A successful canonical Commit does not guarantee C5 admission. The 8,192 diagnostic is a finite default-Budget PASS, not unlimited changed frontier. |

Count boundary matters: `LFS_C1_EDIT_LOAD` counts C1 **edit-tree nodes**;
`LFS_FILE_INPUT` counts Workspace final-input records, and
`LFS_C1_SAVE_COUNT` counts construction. Their totals need not match. A
missing C1 zero was historically **INCOMPLETE** and is never inferred from
another counter. Physical `st_blocks * 512`, quota, Host Budget reservations,
process RSS, container cache/cgroup and phase-local memory are distinct
scopes. A lifetime cgroup peak cannot be presented as a phase peak.
