## Selected architecture and checkpoint-2 exit

LocalEdit attachment in `runtime/host.rs` creates one `ActiveBacking` for the incarnation. `filesystem/active_view.rs` pins one index revision for lookup/list; `N|parent|name` tombstones/bindings merge with canonical `Inspect::List` in byte order. `I` carries current attributes and the selected regular-file link count (v1 bytes `44..48`); `D` is dirty membership; ordered `E` extents name Base, Zero, Packed or Payload content. `P` maps stable logical pack-page IDs to physical pages; `R` and `L` invert packed-slot and large-payload references. One shared pack tail holds 1..128-byte writes across files and Execs. Larger writes retain the existing verified `p-*` PayloadHost owner, with the owner charged to the Host budget. A single index-root change is the publication point for byte/length/attribute/dirty/namespace updates; `runtime/state.rs` moves the matching revision and counters while holding its gate.

`filesystem/active_{create,file,remove,rename,attributes}.rs` are the only mutable public routes. `active_names.rs` owns small shared inode/clock facts. `read.rs` and `symlink.rs` read a pinned active version, then perform Base/Payload I/O outside the active lock. A directory `Handle.view` retains the index pin plus a separately charged `PinnedDirectoryPath` and immutable `ActiveOrigins` map. This keeps a pre-rename directory handle's canonical path paired with its pinned index, while later handles use a moved inherited directory's original canonical path. Regular handles stay bound by inode serial: a replaced or unlinked open file keeps exact old bytes. Link/unlink/replacement update the inode link count with the name row, including zero for an open-unlinked file.

`runtime/coherence.rs` still owns checked FUSE notification. The mounted active EIO test proves a published create returns `WorkspaceError::Coherence` with the exact `MutationReceipt` and retained handle. If backing cleanup itself fails after publication, the new `WorkspaceError::Published` retains receipt, handle and cause after completing checked notification; its public fault-injection proof remains for the reclaim checkpoint. Prepublication quota refusal keeps revision and namespace unchanged. The old mutable `RootOwner` writers in `filesystem/{create,remove,rename,resize,write}.rs` and dead mutation helpers in `overlay/{directories,pieces}.rs` were deleted. Retained old keyed-root decoding/reading in `filesystem/namespace_view.rs`, `write.rs::overlay_inode`, `read.rs::read_overlay`, `overlay/` and `commit/` remains required for old frozen roots and the transition. There is no per-callback legacy writer or dual write.

**Deliberate stage boundary:** `overlay/snapshot.rs::capture_submission` currently returns `Unsupported` for active incarnations. This prevents the old root lowering path from acknowledging an empty or unrelated result. Active dirty `close_clean` returns `Busy`. Those are checkpoint-3 work, not proof of Commit or final cleanup. Checkpoint 2 is complete at the mounted mutable-view boundary; checkpoints 3–5 and release admission are open.
