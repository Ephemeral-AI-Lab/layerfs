The closed, independently verified #271 10 MiB all-`A` Store/history master, hashes and writer schedule remain those in the [Family 3 registry](WORKSPACE-WRITE-REGISTRY-V1-20260930.md). Each case starts with a validated independent writable `shutil.copyfile` copy. The current public SDK has selected-view leases, so it can hold the actual dirty G1 across its first Commit. The old `issue273-clean-commit-v1` and `issue273-one-edit-commit-v1` committed-and-reattached fixtures remain invalid/NOT_RUN under their original specification; no historical receipt is renamed into these new scenarios.

The external launch-to-exit timer pays for Server open, Sandbox create, Mount, the 4,097-write prelude Exec, `pin_view`, prelude Commit, final Exec and Commit, complete old-pin read, checked release, Status, unmount, deletion and shutdown. Prelude construction is **inside** the complete command. No live retained work moves into unmeasured setup. The final SDK Exec/Commit and prelude Exec/Commit spans are separate nested observations, not an invented sum or ratio. Both commands keep the original 15 s ceiling. Every construction uses one worker.

The clean case requires a known `UpToDate` result with exactly the prelude Commit as head. The one-edit case requires a new known Commit with that prelude parent. Both require 4,097 plus their respective 0/1 observed write callbacks. The lease must be pinned before the prelude Commit and held across both Commits. After the final Commit, the SDK reads every pinned `data.bin` byte in 16 KiB requests and hashes it. Its hash must match the harness's independent 4,097-disperse oracle; only 16 KiB view requests are claimed. Checked lease release, unmount and Sandbox deletion must all complete.

`runner.py run --family workspace-commit --out <fresh-path>` is the exploratory fast lane: one attempt per case, verifier `SKIPPED`, full command and cleanup retained. It cannot satisfy independent correctness on its own. At that frozen product/harness identity, `runner.py prove --run <performance-path> --out <fresh-proof-path>` runs the current independent `verify_checkpoint5` once per retained Store/history with a separate 9 s wall and **no performance replay**. It checks the prelude Commit's parent against the sealed master Commit, both complete old/new trees/modes/bytes against independent manifests, and exact final parentage or clean unchanged head. The verifier now checks both manifests even for `UpToDate`. Proof files live in a new output directory; performance receipts stay immutable. Evidence manifests are checked before and after proof, including that the verifier did not mutate the retained Store/history.

Builds are locked release in the owned worktree. The daemon image may be reused only when its daemon binary, static writer and Dockerfile hashes all match, and Docker confirms the exact image ID. The SDK driver/verifier are built incrementally and archived by SHA-256. Every round records actual reuse rather than rebuilding the same image to obtain a new identity.

The full Commit cache domain remains unproved, as corrected in the [r044 audit](experiments/20260930-workspace-write-r044-cache-audit.md). Numeric latency therefore stays `INELIGIBLE`; command-bound, independent correctness and cleanup verdicts are separate. A functional PASS cannot manufacture speed admission.
