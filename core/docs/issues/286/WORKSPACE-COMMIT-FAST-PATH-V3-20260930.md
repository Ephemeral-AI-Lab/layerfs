# Family 4 v3: fast controls and separate full pin oracle

> **Status:** Prospective correction after the immutable [v2 r048 timeout](experiments/20260930-workspace-commit-fast-r048.md). Committed before new collection. The v2 case IDs, 15 s limit and failed/unrun receipts remain unchanged.

The v2 driver performed the full pinned-byte verifier inside its 15 s performance command; its first case timed out after 53/640 reads despite both Commit calls completing. The owner's fast-path direction and general benchmark contract separate verification from performance. The **new v3 IDs** therefore measure the same retained product operations with a metadata-only lease-custody observation. They do not claim a full pin byte proof from that observation.

All rows clone the same closed #271 master with byte/hash checks, use one writer and one construction worker, and retain the exact prelude schedule `B+(i%24)` at `(104729+i*2654435761)%10485760`. Prelude construction, pin acquisition, both Commits, final Exec, held-lease status, checked release, Status, unmount, Sandbox deletion and shutdown remain inside each external wall. A full independent canonical verifier remains separately bounded by 9 s per retained Store/history, invoked once through `runner.py prove`; it does not replay performance. The complete pin functional case is a distinct route/role with no latency claim. It cannot replace a failed performance row or silently relabel v2.

The fast rows record `pin_status` for held generation/custody and `pin_verification_status=SKIPPED`. They remain independent-correctness `INCOMPLETE` until their separate old/new canonical proofs pass. The functional oracle additionally requires the complete held G1 digest to match the independently derived 4,097-disperse bytes, successful checked release, old/prelude/new Commit chain and complete canonical old/new bytes. Reuse of that same-source functional pin proof is explicit; no sampled read is described as a full oracle.

The 31 KiB batch is prospectively declared. Code inspection found that `adapters/native/protocol/frame.rs` bounds terminal Success frames by `METADATA_BYTES=32768`, while `workspace_view.rs` encodes view-byte length as `u16`, despite the SDK's advertised 128 KiB request ceiling. This records a source-backed capability limitation, not a new live 32/128 KiB result. The functional selection requests 31,744 bytes directly, with no error-triggered smaller fallback. The previous unresolved 32 KiB SDK observation is not qualified by these reads. Fixing the production framing/length contract would be a separate disruptive change with its own architecture and scoped regression work.

Full-command numeric cache admission remains `INELIGIBLE` under the [r044 correction](experiments/20260930-workspace-write-r044-cache-audit.md). The unchanged 15 s command gate, canonical/pin correctness, custody, cleanup and numeric eligibility stay separate. Remaining Family 4 lowering, occupied headroom, reordered copies, live G1/G2, failures and deterministic SDK stopping selections remain visible. Earlier-family evidence is reused for this benchmark/example-only change; Family 2 is not rerun.

Fast default: `runner.py run --family workspace-commit --out <fresh-path>`. Separate retained proof: `runner.py prove --run <fast-path> --out <fresh-proof-path>`. Full pin oracle: `runner.py run --case workspace-commit-full-pin-retained-writes-4097-read-31kib-v1 --out <fresh-path>`, followed by its separate `prove` invocation. Every command has one attempt at its frozen identity, and every failure/timeout/unrun outcome is append-only.
