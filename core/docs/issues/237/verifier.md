## Actual read graph

1. The child authenticates the sealed manifest, opens C5 history, checks the returned root against its recorded layer, and opens C2 Store ([`verify_namespace.rs:171-206`](../../../crates/layerfs-service/examples/verify_namespace.rs#L171-L206)). It then walks every directory through public C1 `list` and `lookup_inodes`, checks every directory's metadata, and insists the actual path set equals the manifest set ([`verify_namespace.rs:207-249`](../../../crates/layerfs-service/examples/verify_namespace.rs#L207-L249)). Each `list` resolves its directory path first ([`filesystem/read.rs:143-164`](../../../crates/layerfs-content/src/filesystem/read.rs#L143-L164)); listing has no retained cursor state across calls ([`directory/read.rs:187-259`](../../../crates/layerfs-content/src/filesystem/directory/read.rs#L187-L259)). In this 100-child-per-directory fixture, the 128-entry bound needs only one page per directory, so repeat pagination is not the dominant source-linked work. `lookup_inodes` already groups demands by tree level ([`inode/read.rs:84-147`](../../../crates/layerfs-content/src/filesystem/inode/read.rs#L84-L147)).
2. Four workers pop the 10,000 queued files. For **every file**, each worker calls `check_metadata`, then streams its entire content through public C1 `read_all` into SHA-256 and compares both byte count and digest with the sealed manifest ([`verify_namespace.rs:114-169`](../../../crates/layerfs-service/examples/verify_namespace.rs#L114-L169)). A file read is one authenticated root demand for a whole-file object; chunked files add bounded navigation and payload waves ([`file/read.rs:18-57,92-125`](../../../crates/layerfs-content/src/file/read.rs#L18-L57), [`file/mapping/read.rs:184-215,246-315`](../../../crates/layerfs-content/src/file/mapping/read.rs#L184-L215)). The 10k manifest declares 300,000,000 logical bytes, including one 100,000,000-byte anchor ([`init_namespace.py:28-33,40-59`](../../../benchmark/fs-bench-pro/families/init_namespace.py#L28-L33)); all of those bytes still require reopened C1 readback and a SHA-256 comparison.
3. `check_metadata` calls C1 `read_portable` on each inode's `metadata_root` ([`verify_namespace.rs:91-111`](../../../crates/layerfs-service/examples/verify_namespace.rs#L91-L111)). `read_portable` descends the attribute tree once for mode and mtime, then reads two extent-backed value roots ([`attributes/read.rs:112-145`](../../../crates/layerfs-content/src/filesystem/attributes/read.rs#L112-L145)). Each value root costs one file-state demand plus nonempty mapping-page and chunk-payload demands ([`attributes/value.rs:61-91`](../../../crates/layerfs-content/src/filesystem/attributes/value.rs#L61-L91), [`file/mapping/read.rs:325-350`](../../../crates/layerfs-content/src/file/mapping/read.rs#L325-L350)). For this two-key leaf, that is **seven C2 waves per metadata check**: one attribute page, and three for each value. This is a source-derived count, not a measured D6 counter. `StoreProvider` retains one connection and decoded-body caches per worker, but each wave still locks Store arbitration, refreshes publication/scope/pack ceiling, and runs object-locator SQL ([`provider.rs:66-82,118-175`](../../../crates/layerfs-storage/src/cas/provider.rs#L66-L82), [`cas/read.rs:249-271`](../../../crates/layerfs-storage/src/cas/read.rs#L249-L271), [`sqlite/lookup.rs:69-109`](../../../crates/layerfs-storage/src/sqlite/lookup.rs#L69-L109)). Four readers do not parallelize that locked portion.

## Highest-value, bounded change

The sealed 10k manifest has 10,000 regular files with mode `416` (`0o640`) and the same mtime, plus 101 directories with mode `488` (`0o750`) and that same mtime. This was counted from the retained `manifest.tsv`; its class counts and generation are specified by [`init_namespace.py:28-59,110-140`](../../../benchmark/fs-bench-pro/families/init_namespace.py#L28-L59). The importer deliberately reuses adjacent equal portable metadata, and the two-key metadata construction is canonical and content-addressed ([`history_bootstrap.rs:259-283,342-367`](../../../crates/layerfs-service/src/operation/history_bootstrap.rs#L259-L283)). Therefore the expected Store shape is one metadata-root ID for all files and one for all directories; count actual distinct IDs in a labelled diagnostic before treating that expectation as an observation.

Implement the smallest full-oracle-preserving verifier change in [`verify_namespace.rs`](../../../crates/layerfs-service/examples/verify_namespace.rs): give `check_metadata` a mutable `Option<(ObjectId, InodeKind, PortableMetadata)>` and reuse the checked metadata only when **both** the inode's authenticated `metadata_root` and kind match. Keep one slot for the directory walker and one per file worker. On a miss, use the existing `read_portable`, then update the slot after success. On **every** path, still compare the inode kind, mode, and mtime to that path's manifest row. Never use the expected manifest fields to fill the cache. A single slot is constant-memory and handles heterogeneous imports correctly, though alternating distinct metadata roots simply miss more often. `PortableMetadata` is `Copy` ([`portable.rs:15-24`](../../../crates/layerfs-content/src/filesystem/attributes/portable.rs#L15-L24)); `InodeKind` is `Copy` and `Eq` ([`inode_leaf.rs:50-59`](../../../crates/layerfs-content/src/object/inode_leaf.rs#L50-L59)). No new API, dependency, Store policy, page-size change, or worker count is needed.

If the D6 shape really has two metadata roots, the theoretical metadata work falls from `10,101 × 7 = 70,707` C2 waves to at most `(1 directory slot + 4 file slots) × 7 = 35` waves, saving **70,672** waves. This is an algorithmic work prediction, **not** an observed time reduction or verifier PASS. The retained 5 s timeout exposes no phase counters, so content read/decompression/hash cost may still prevent completion. Do not replace full content reads with object-ID comparison, source-fixture hashes, raw SQL, or sampled paths; those would weaken the oracle.
