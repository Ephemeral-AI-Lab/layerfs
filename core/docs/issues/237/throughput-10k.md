# #237: what 700 MB/s means for the 10k public Init

> **Status:** Research; informative and not a product contract.
> Research note, 2026-09-23. This reads retained receipts and source only. It adds no performance sample, changes no product or benchmark policy, and makes no admission claim. The current Core reference is the D9 release-profile binary identity at source `2a66f84d`; the historical rows have different source, fixture, cache and route identities.

## Numerator, timer, and historical custody

`namespace-10000` contains 10,000 files, 100 data directories and **300,000,000 logical bytes total**. Its 100,000,000-byte anchor is **inside** that total: the reference generator subtracts the anchor before distributing the remainder ([registry](../../../../benchmark/fs-bench-pro/families/init_namespace/mod.rs#L71-L85), [generator](../../../../benchmark/fs-bench-pro/workload/main.rs#L332-L344)). The reference product divides the manifest's `logical_bytes` by `layerstack_init_ns`, a timer around one public `client.initialize_layerstack(Directory(fixture))` call. Store creation and teardown are outside it ([timer](../../../../benchmark/fs-bench-pro/src/main.rs#L2958-L3017)).

On that definition, the historical 578.245 ms row is **518.8 MB/s**, not 691.8 MB/s: the latter uses 400 MB and double-counts the anchor. The two 402.721/407.598 ms rows are 744.9/736.0 MB/s, but both have dirty source trees, no declared cold contract, `verification_status=NOT_RUN`, almost no process disk reads, and about 54.46k canonical objects. The later clean, 25,158-object rows took 1,020.422/1,100.711 ms while reading 337.4/322.2 MB from storage: 294.0/272.6 MB/s. All eight historical 10k receipts are labelled `candidate`; none is a true baseline ([retained inventory](../../../../docs/roadmap/0.1/0.1.7/evidence/issue219-s0-custody-20260921T031259Z/README.md#1-receipt-inventory--every-namespace-10000-row-located), [CPU and object counts](../../../../docs/roadmap/0.1/0.1.7/evidence/issue219-ns19r-algogap-20260921T095811Z/README.md#step-1--the-commissions-1a-is-re-derived-and-it-holds)). A sealed reference reproduction was 944.881 ms, **317.5 MB/s**, after scanning 300 MB but reading only 0.729 MB from storage; its cache contract was null ([#219 S1](../../../../docs/roadmap/0.1/0.1.7/evidence/issue219-s1-reproduction-20260921T031259Z/README.md#1-the-result)). These are historical observations, not a matched cold 700 MB/s precedent.

The current Core timer surrounds one daemon `ImportNativeDirectory` request and stops after its confirmed C5 root reply ([driver](../../../benchmark/fs-bench-pro/families/init_namespace.py#L155-L176)). It includes source scan/read, four file constructors and C2 save, C1 namespace construction and C5 publication ([Service path](../../../crates/layerfs-service/src/operation/history.rs#L305-L345)). The #219 `pipeline-namespace-10000` timer instead starts after content construction and excludes the source scan; its subsecond operation cannot substitute for this Init ([boundary audit](../../../../docs/roadmap/0.1/0.1.7/evidence/issue219-squadD-chunk-20260921T044229Z/README.md#21-the-two-timers-are-not-equivalent)). Core and v0.1.6 also distribute file sizes differently and generate different bytes, despite identical file/byte counts ([Core plan](../../../benchmark/fs-bench-pro/families/init_namespace.py#L40-L59), [reference plan](../../../../benchmark/fs-bench-pro/workload/main.rs#L273-L344)).

## Present release-profile budget

The retained D9 Core receipt used exact sealed `--release` binaries, one public sample, and returned a C5 root in **1.590847333 s**: **188.58 MB/s**. Its independent immediate mincore check found **0 resident pages among 27,503 checked** across all 10,000 files/300 MB and ended 1.061 ms before the public timer ([receipt](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/raw/d9-release-fast/daemon-host/init_namespace/namespace-10000/receipt.json), [cold recheck](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/raw/d9-release-fast/daemon-host/init_namespace/namespace-10000/cold-recheck.json), [build](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/raw/d9-release-fast/build.json)). The frozen runner still labels it `source-cache-uncontrolled-v1`, `admission_eligible=false`, and verifier `SKIPPED`; the sidecar does not retroactively grant admission. Its SQLite page size was **4,096 bytes** ([geometry](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/raw/d9-release-fast/store_geometry.json)).

For 700 **decimal** MB/s over 300 MB, the complete public call must finish in **0.428571 s**. Relative to D9, that requires **1.162276 s less**, a **73.1%** wall reduction or **3.71x** speedup. D9's Service child `history.import_files` alone took **1.249614 s**, 78.6% of the caller interval; even if every other span cost zero, that stage caps the rate at **240.1 MB/s**. It must shrink by at least **0.821042 s** to fit the entire target. Its scan was 40.763 ms and `finish_tree_save` 30.133 ms; these cannot by themselves close the gap. The current four constructors and eight-message handoff are in [the actual file path](../../../crates/layerfs-service/src/operation/import_native.rs#L143-L189). The file span is concurrent producer/owner work; adding its CPU, C2 timings, and source read time would double-count overlap. A count-driven breakdown of source reads, worker construction, sender blocking, receiver idle, and owner accept is needed before choosing an algorithmic treatment ([existing handoff analysis](file-ingest.md#one-prospective-diagnostic-then-the-smallest-justified-treatment)).

The daemon is not the observed second-scale bottleneck. D9's daemon `HistoryCommand` telemetry span was **1.590682 s**, while the Service span was **1.590234 s**, a **0.448 ms** difference; the public driver timer exceeded the Service span by **0.614 ms**. These are durations in separate local clocks, and their small difference is **not** an exact transport cost or a guaranteed upper bound. It does show that deleting the daemon cannot plausibly supply the missing 1.162 s without changing work inside the Service. The driver reads one framed result ([headless route](../../../crates/layerfs-daemon/src/headless.rs#L23-L75)); the Service owns the scan, file save, tree and C5 work cited above. The 2.018 s complete-command wall includes startup, cleanup and a 0.373 s source-residency recheck; it is a different metric from the 700 MB/s public-call denominator ([runner boundary](../../../benchmark/fs-bench-pro/runner.py#L282-L303), [D9 recheck](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/raw/d9-release-fast/daemon-host/init_namespace/namespace-10000/cold-recheck.json)).

The #151 record's **2.1 GiB/s** storage read came from a different 500 MiB payload/route, so it is only a hardware-scale illustration, not a measured lower bound for D9's many-file source ([ledger L18](../../../../docs/roadmap/0.1/0.1.6/evidence/issue151-experiment-ledger.md#l18--the-b2-payload-must-be-read-from-storage-not-its-own-page-cache)). At that rate, 300 MB alone would take about **0.133 s** and leave about **0.296 s** of a 0.429 s target for everything else *if* reading were serial. Real reading, hashing, construction and saving overlap; measure their critical path on the same cold fixture rather than adding this illustration to the D9 phases or comparing to cache-served v0.1.6 rows.

## Proof needed for a cold 700 MB/s claim

Freeze one public 10k route, fixture bytes/path layout, release compilation seal, four-worker policy, 4 KiB SQLite page size, Store policy and cache contract before a control/treatment pair. Invalidate source pages after preparation and confirm whole-input zero residency immediately before **each** caller timer; retain the source-read counters and any failure. Compare one sample per arm with the same timer and record the returned C5 root, full independent readback, CPU, bounded memory, Store bytes/pack occupancy and the separate #229 sparse-pack result. A new host-direct SDK route from #236 needs its own route label and pair. No historical warm row or supplied-object pipeline timer proves the cold public target.
