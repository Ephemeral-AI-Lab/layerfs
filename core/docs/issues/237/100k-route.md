# #237: making native `namespace-100000` runnable

> **Status:** Research; informative and not a product contract.
>
> Source audit only, 2026-09-23. No 100k run, production edit, benchmark limit change, or performance claim was made for this note. The current Core runner's 100k status is `NOT_RUN`. This page is an implementation handoff, not a revision of #231's first-pass receipts or contract.

## Existing case and the exact hard skip

- Core already declares `namespace-100000`: 100,000 regular files, 1,000 data directories, **500,000,000 total logical bytes**, two 100,000,000-byte anchors, and class counts `(2, 1,000, 78,998, 15,000, 5,000)` in [`families/init_namespace.py:28-34`](../../../../core/benchmark/fs-bench-pro/families/init_namespace.py#L28-L34). `plan()` assigns 100 files per directory and apportions the non-anchor remainder by integer weights in [lines 40-59](../../../../core/benchmark/fs-bench-pro/families/init_namespace.py#L40-L59). Source profile is `core-native-import-fixture-v2`, route is `core-native-directory-import-v2`, seed is 1, and bytes are written as SHAKE-256 chunks with fixed modes and mtime in [lines 12-15, 96-144](../../../../core/benchmark/fs-bench-pro/families/init_namespace.py#L96-L144). The fixture manifest contains every path, kind, mode, mtime, size and SHA-256.
- The current legacy registry also declares **500,000,000 total bytes including the two 100 MB anchors**: its workload subtracts `anchor_files * anchor_bytes` from `scenario.logical_bytes` before apportioning the remainder ([`workload/main.rs:324-344`](../../../../benchmark/fs-bench-pro/workload/main.rs#L324-L344)). Its 100k class counts and byte total therefore match this Core declaration ([`families/init_namespace/mod.rs:86-100`](../../../../benchmark/fs-bench-pro/families/init_namespace/mod.rs#L86-L100)). **The fixture content does not match:** legacy role permutation and content generation differ from Core's ordered SHAKE-256 plan; Core's changed content identity is explicit in [`SPEC.md:116-132`](../../../../core/docs/benchmark/fs-bench-pro/issue-231/SPEC.md#L116-L132). Do not copy the legacy `FIXTURE_DIGEST` into Core or infer equal content from matching counts/bytes. Some #219 prose describes a 10k 300 MB corpus *plus* a 100 MB anchor, while the current legacy workload computes 300 MB **including** its anchor; settle that historical receipt/source identity before any 10k speed factor.
- The omission is deliberate first-pass policy, not a product entry-count cap: `SELECTED` takes only the first three cases ([`init_namespace.py:36-37`](../../../../core/benchmark/fs-bench-pro/families/init_namespace.py#L36-L37)); `run()` explicitly bypasses the 100k case ([`runner.py:522-527`](../../../../core/benchmark/fs-bench-pro/runner.py#L522-L527)); CLI validation rejects a direct `--case namespace-100000` ([`runner.py:560-563`](../../../../core/benchmark/fs-bench-pro/runner.py#L560-L563)); and `verify_run()` demands its receipt remain `NOT_RUN` with zero samples ([`runner.py:466-472`](../../../../core/benchmark/fs-bench-pro/runner.py#L466-L472)). `_fill_not_run()` publishes that receipt ([`runner.py:490-499`](../../../../core/benchmark/fs-bench-pro/runner.py#L490-L499)). All four places and the focused test asserting the three-case selector ([`tests/test_init_namespace.py:11-19`](../../../../core/benchmark/fs-bench-pro/tests/test_init_namespace.py#L11-L19)) need a **prospective** registry/contract version change. Old evidence must keep the old verifier interpretation.
- #231 explicitly left this tier out of its first pass and did not relax its 2.7 s historical cold target ([`SPEC.md:32-41, 55-60, 342-353`](../../../../core/docs/benchmark/fs-bench-pro/issue-231/SPEC.md#L342-L353)). The retained first-pass report has zero 100k samples and a 10k failed root at 13.050897750 s, 15.120518875 s command wall ([`RESULTS-20260923.md:44-66`](../../../../core/docs/benchmark/fs-bench-pro/issue-231/RESULTS-20260923.md#L44-L66)). Thus scale to 100k cannot be inferred from that attempt.

## Current public route and scaling obligations

1. **Daemon-host.** The existing runner starts a fresh Store and host Service configured with `LAYERFS_IMPORT_ROOT`, then a host daemon, and times one `HistoryCommand::ImportNativeDirectory` caller request ([`runner.py:236-300`](../../../../core/benchmark/fs-bench-pro/runner.py#L236-L300), [`init_namespace.py:155-176`](../../../../core/benchmark/fs-bench-pro/families/init_namespace.py#L155-L176)). The Service operator binds the source at startup ([`native/startup.rs:91-93`](../../../../core/crates/layerfs-service/src/native/startup.rs#L91-L93), [`owner.rs:106-113`](../../../../core/crates/layerfs-service/src/owner.rs#L106-L113)). Service scans and saves, reserves serials, builds the C1 tree, and publishes C5 before returning `StackCreated` ([`operation/history.rs:305-345`](../../../../core/crates/layerfs-service/src/operation/history.rs#L305-L345)). Keep source scan and reads inside this one public timer.
2. **Host-direct SDK.** #236 owns `init_project(project_name, path)` and safe request-scoped source binding; it must not race by swapping `LAYERFS_IMPORT_ROOT`. Once delivered, register a distinct host-direct route and its exact SDK binary/product/fixture identity. Call the same Service/C1/C2/C5 import body with per-call source selection, time the full public SDK operation and verify its returned C5 root. Do not relabel daemon-host timings as host-direct. This is the stated [#236 contract](https://github.com/Ephemeral-AI-Lab/layerfs/issues/236) and [#237 scope](https://github.com/Ephemeral-AI-Lab/layerfs/issues/237), not code already present in this worktree.
3. **Deadline and progress.** Today the daemon-host driver sets a 15,000 ms absolute request deadline and a 15 s receive watchdog ([`init_namespace.py:159-165`](../../../../core/benchmark/fs-bench-pro/families/init_namespace.py#L159-L165)). The request validator requires `response_bytes >= ceil(deadline_ms/1000)` for native import, so 15 s requires at least 15 marker bytes ([`request.rs:359-369`](../../../../core/crates/layerfs-bridge/src/contract/request.rs#L359-L369)); the existing frame driver declares 64 MiB ([`history_route.py:34-35`](../../../../core/crates/layerfs-daemon/tests/history_route.py#L34-L35)). The Service progress emitter writes a one-byte marker on a one-second `tick()` and checks the same absolute deadline ([`history_bootstrap.rs:46-83`](../../../../core/crates/layerfs-service/src/operation/history_bootstrap.rs#L46-L83)); the native client validates and consumes this byte without counting it as logical result data ([`native/client.rs:151-180`](../../../../core/crates/layerfs-bridge/src/adapters/native/client.rs#L151-L180)). The contract retains the transport's five-second no-progress limit ([`SPEC.md:91-106`](../../../../core/docs/benchmark/fs-bench-pro/issue-231/SPEC.md#L91-L106)). Audit long C1 `build_filesystem`/C2 `finish` spans: `build_namespace` ticks before and after the synchronous build, not inside it ([`history_bootstrap.rs:168-221`](../../../../core/crates/layerfs-service/src/operation/history_bootstrap.rs#L168-L221)). A stall there may expire progress or deadline. Report it; do not widen either clock to manufacture completion.
4. **Work and memory.** The source scan sorts each directory's ~100 children and stores one `PreparedEntry` plus one `Job` per file before construction ([`import_native.rs:59-113`](../../../../core/crates/layerfs-service/src/operation/import_native.rs#L59-L113)). Four construction workers share a job queue and an eight-message handoff to one C2 save owner ([`import_native.rs:143-189`](../../../../core/crates/layerfs-service/src/operation/import_native.rs#L143-L189)); file construction streams from `File` and checks inode/length/mtime stability ([`import_native.rs:191-229`](../../../../core/crates/layerfs-service/src/operation/import_native.rs#L191-L229)). `build_namespace` allocates O(entries) serials/inodes/directory bindings and an on-disk ordering scratch, then saves prerequisites and tree ([`history_bootstrap.rs:113-221`](../../../../core/crates/layerfs-service/src/operation/history_bootstrap.rs#L113-L221), [242-328](../../../../core/crates/layerfs-service/src/operation/history_bootstrap.rs#L242-L328), [376-402](../../../../core/crates/layerfs-service/src/operation/history_bootstrap.rs#L376-L402)). No arbitrary count refusal is visible in this path, but 100k is **not constant-memory**: the fixture plan, source scan and C1 input hold O(100k) metadata. Measure actual heap/RSS, scratch, page cache and Store separately; a bound must include these retained structures rather than calling the eight-object handoff a bound on total memory. Keep Init's registered four workers; do not alter worker, SQLite cache, or 4 KiB `PRAGMA page_size` to pass a row. The existing Store test checks 4,096 bytes ([`connection_profile.rs:100-112`](../../../../core/crates/layerfs-storage/tests/connection_profile.rs#L100-L112)).

## Cold-source and full-proof contract to freeze before first 100k row

- **New Core cold identity, same hard method.** Legacy [`shared/cold.py:13-25`](../../../../benchmark/fs-bench-pro/shared/cold.py#L13-L25) applies only to the legacy `init_namespace/namespace-100000` route. Its `FIXTURE_DIGEST`, `layerstack_init_ns` timer, `initialization_disk_read_bytes`, and historical row schema are legacy-specific ([`cold.py:186-250`](../../../../benchmark/fs-bench-pro/shared/cold.py#L186-L250)); Core currently records `source-cache-uncontrolled-v1` and `admission_eligible=false` ([`runner.py:240-244`](../../../../core/benchmark/fs-bench-pro/runner.py#L240-L244)). Reuse only the tested Darwin mechanism: positive mincore self-check, source content/metadata validation, per-file invalidation after any setup read/write, and a separate nonfaulting mincore pass over **every** file that reports `files_checked=100000`, `logical_bytes=500000000`, `pages_checked=expected_pages`, `resident_pages=0`, matching sealed manifest, and a recorded short preflight-to-timer gap ([`cold.py:28-80, 113-183, 218-236`](../../../../benchmark/fs-bench-pro/shared/cold.py#L113-L183)). A host-direct case must qualify the same host source pages it actually reads. If any page is resident or evidence is missing, retain the attempt as `INELIGIBLE`; do not rerun unchanged merely to obtain zero. The current research sidecar implements the basic per-file invalidate/whole-input pattern only for 1k/10k and labels itself diagnostic ([`cold_diagnostic.py:19-49`](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/cold_diagnostic.py#L19-L49)); extending it is not automatically an admission contract.
- **Actual-output oracle.** On `--verify`, the runner starts a separate child with a fixed 5 s watchdog and passes the returned root, stack body and sealed manifest ([`runner.py:208-233`](../../../../core/benchmark/fs-bench-pro/runner.py#L208-L233)). That child reopens C5 history and C2 Store, checks the recorded genesis root, walks **all** paths with 128-entry pages and grouped inode lookups, compares portable metadata, and streams every file through public C1 reads into SHA-256 with four read workers ([`verify_namespace.rs:171-254`](../../../../core/crates/layerfs-service/examples/verify_namespace.rs#L171-L254), [114-169](../../../../core/crates/layerfs-service/examples/verify_namespace.rs#L114-L169)). At 100k it must report 101,001 paths, 100,000 files, 1,001 directories and 500,000,000 bytes with matching manifest/root. The 5 s proof bound may fail; report `TIMEOUT` with the full raw output and cost, never sample, shrink, or silently extend the oracle. A default `SKIPPED` verifier cannot clear the case ([`runner.py:299-329`](../../../../core/benchmark/fs-bench-pro/runner.py#L299-L329)).
- **Prospective numeric/resource/space rule.** Freeze the route, fixture SHA-256, seed, cache method, timer, build profile, exact cold target status, complete-command and verifier budgets, CPU/RSS/scratch/Store ceilings, and telemetry/custody requirements before the sample. Existing 15 s complete-command and 5 s verifier bounds are in [`SPEC.md:342-353`](../../../../core/docs/benchmark/fs-bench-pro/issue-231/SPEC.md#L342-L353); the 2.7 s historical cold target stays visible, never an inherited PASS. Pin `PRAGMA page_size=4096`, physical Store bytes, `sum(length(data))`, allocated/live pack bytes, pack utilization and reopened full readback. Compare the Init corpus and #229 sparse-history lane at matched product/fixture identities; a faster Init that repeats the sparse-pack expansion is a no-go ([#237 acceptance](https://github.com/Ephemeral-AI-Lab/layerfs/issues/237)). Treat preparation and cold preconditioning as separate recorded wall costs; the complete command must still expose lifecycle and cleanup wall. Current `runner.py` builds debug binaries ([`runner.py:26-30, 96-125`](../../../../core/benchmark/fs-bench-pro/runner.py#L26-L30)) although `SPEC.md` describes a release build ([`SPEC.md:355-359`](../../../../core/docs/benchmark/fs-bench-pro/issue-231/SPEC.md#L355-L359)); resolve and freeze this identity before comparing any future row.
