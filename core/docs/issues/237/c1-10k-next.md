# #237: next C1 experiment for the 10k native Init

> **Status:** Research; informative and not a product contract.
> Hypothesis only; not a measured improvement or admission result. D9 is pinned to release source `2a66f84d975bff281c5117436b0a7d60e62ffb16`; the current research checkout is `a6d1d563f98b40755c43684a0449c74d39d894ff`. This note made no product, harness or benchmark sample changes.

## What D9 establishes

The retained [D9 receipt](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/raw/d9-release-fast/daemon-host/init_namespace/namespace-10000/receipt.json) records a 1.590233583 s Service operation. Its named children sum to 1.332907124 s, leaving **0.257326459 s unattributed**. This remainder includes C1, Service input assembly, scratch setup/cleanup, and any unnamed publication work; it is **not a direct C1 timer**. The named `history.import_files` child alone is 1.249613667 s, while `history.finish_tree_save` is 0.030132750 s. Even a 0.050 s remainder would leave about 1.383 s total, so a 300 MB / 0.429 s public target also needs a large improvement in file ingest.

The retained [Store geometry](../../../../docs/roadmap/0.1/0.1.7/evidence/issue237-native-init-research/raw/d9-release-fast/store_geometry.json) has SQLite `page_size=4096`, 334,184,448 physical bytes, and 308 objects in the tree save. A read-only `sqlite3` query of the retained D9 Store grouped `objects` by `save_id, object_role`: save 3 contains 202 inode leaves (827,069 canonical bytes), 101 directory leaves (175,944 bytes), 4 inode branches (8,376 bytes), and one filesystem root (129 bytes). These are output counts, not C1 time attribution. Preserve their canonical root and the Store's physical/pack/readback results in a candidate.

## Source-derived work still on the `base=None` route

The Service assigns 10,101 consecutive serials, supplies sorted inode values and new IDs, and calls C1 with `base: None` and default resources ([builder](../../../crates/layerfs-service/src/operation/history_bootstrap.rs#L124-L167)). C1 validates the full topology, creates the reference reducer, and registers all 10,101 values ([update](../../../crates/layerfs-content/src/filesystem/update.rs#L157-L180), [registration](../../../crates/layerfs-content/src/filesystem/update.rs#L469-L488)). Directory merges then observe 10,100 added bindings, the 101 rebuilt directories receive new values, and **all 10,000 file values are supplied a second time** ([directory observation](../../../crates/layerfs-content/src/filesystem/update.rs#L184-L303), [later values](../../../crates/layerfs-content/src/filesystem/update.rs#L304-L359)). Thus this native shape makes 30,302 reducer `entry` requests before finalization. The `base=None` route does not run the zero-count release walk ([guard](../../../crates/layerfs-content/src/filesystem/update.rs#L360-L386)).

The existing gap fix prevents repeated scans across proven-empty serial intervals, but it does not remove spill work. With the frozen ascending fixture and 4,096 pending-row ceiling, a deterministic replay of [`entry`/spill](../../../crates/layerfs-content/src/filesystem/references/reduce.rs#L233-L263), [binary-tier merging](../../../crates/layerfs-content/src/filesystem/references/runs.rs#L223-L323), and [final consolidation](../../../crates/layerfs-content/src/filesystem/references/runs.rs#L398-L471) predicts **83,551 fixed-width run rows written**, or 8,020,896 bytes at [96 bytes per row](../../../crates/layerfs-content/src/filesystem/references/record.rs#L25-L26). The model's accounting is 28,672 spill rows + 34,677 pre-final merge output rows + 20,202 final-consolidation output rows. This is source-model work, not a D9 measured counter. Each spill and merge currently calls `OrderingRun::append` per row ([spill](../../../crates/layerfs-content/src/filesystem/references/runs.rs#L249-L259), [merge](../../../crates/layerfs-content/src/filesystem/references/merge.rs#L221-L249)); the file backing does a `write_all` per append ([backing](../../../crates/layerfs-content/src/filesystem/references/backing.rs#L313-L336)). It also reads runs and builds a final run before streaming the same 10,101 final rows into the sorted inode builder ([finish](../../../crates/layerfs-content/src/filesystem/references/reduce.rs#L265-L291), [inode builder](../../../crates/layerfs-content/src/filesystem/update.rs#L387-L419)). These counts make the reducer a plausible part of the 0.257 s remainder, but D9 did not isolate its time.

## One candidate: stream a new filesystem directly after validation

**Hypothesis:** for `base=None` where every supplied inode is declared new and the existing caller-owned ordering backing is present, C1 can omit the reference reducer and its scratch runs. This is a general new-filesystem condition, not a benchmark ID switch. Keep the existing generic path for updates and for other input shapes; choose the path before mutation, with no error-driven fallback.

Validation already allocates `CheckedInput.additions`, a `BTreeMap` with one key for **every** bound child, including files whose values currently remain zero ([allocation and final fill](../../../crates/layerfs-content/src/filesystem/validate.rs#L173-L177), [all bindings](../../../crates/layerfs-content/src/filesystem/validate.rs#L289-L309)). Reuse that map as the observed count owner: after validation, zero its values; during each directory merge, increment the map for every observed `after` binding, with the same checked overflow and addition counter as the reducer. For a parent intentionally skipped as unreachable, count its stated `Some` bindings at the existing manual observation site. A new build has no base binding to remove, so an observed `before` is an error. This preserves the current rule that final reference counts come from **edges the directory operation observed**, rather than trusting caller-supplied counts ([current observer](../../../crates/layerfs-content/src/filesystem/update.rs#L240-L267)).

After directory roots are known, walk the already sorted `input.inodes` once. For each non-dropped serial, require the same declared-new membership and a positive observed count except for the root; replace its content root from the rebuilt-directory map if present; set `namespace_ref_count` from the observed map; and pass the iterator to the existing `apply_inode_values(objects, None, ...)` ([current final builder](../../../crates/layerfs-content/src/filesystem/update.rs#L395-L410)). Preserve the existing error for a supplied new inode with no binding and the existing rejection of a bound inode lacking a typed value. An initial build's root keeps count zero. Keep validation, sorted-directory construction, C2 handoff, ordering resource checks and checked cleanup in the same public call. The one map is already allocated by validation, so this adds no entry-count-sized collection; bounded sorted-engine scratch remains unchanged. It should emit the same sorted `(serial, InodeValue)` stream and therefore the same canonical inode table and filesystem root **if** the observed-edge and error cases pass the checks below.

This removes the 30,302 reducer requests, the modeled 83,551 run-row writes and associated merges/reads for the selected initial-build shape. It does **not** remove 10,100 binding observations, 10,101 final inode values, 308 canonical tree objects, validation, or C2 admission. Reaching ≤0.050 s of unnamed work is a testable target, not an estimate supported by D9.

## One prospective experiment and decision rule

1. First make one labelled, unmerged **count-driven diagnostic** from the existing D9 release identity: call the already implemented `build_filesystem_timed` with `FilesystemPhases::new` from the Service's C1 build scope ([phase API](../../../crates/layerfs-content/src/filesystem/objects.rs#L127-L165), [timed entry](../../../crates/layerfs-content/src/filesystem/update.rs#L80-L91)). Retain `validate`, directory, reference, inode, cleanup and root spans plus `FilesystemUpdateCounters`, `runs.rows_written/read`, scratch peak, C2 save counters, and the complete public timing. The `references` phase only covers final consolidation; count the earlier reducer work around registration, binding and second-value stages separately. If reducer work is a small fraction of 0.257 s, do not build this candidate.
2. If it dominates, prototype only the direct `base=None` path as an unmerged research diff. One external C1 check should compare generic versus direct roots and emitted object IDs/bytes for the frozen 10k shape, hardlinks, symlinks, an empty root, disconnected new inodes, and an unreachable new parent; include a tiny pending ceiling to force the generic spill path. Check exact failure behavior, ordering-byte/peak scratch bounds and cleanup. Keep the product's 4 KiB SQLite page size and all canonical formats unchanged.
3. Take one prospectively declared public 10k diagnostic at the new source identity, with the same sealed 300 MB fixture, release build, cold-source check, route, request/command limits, worker count and Store policy. Record the full receipt and every failure. Compare C1 count/time attribution, public time, CPU, RSS, scratch, physical Store size, pack utilization, canonical root and full reopened readback to the retained control. Treat verification as separate from performance under the current AGENTS rule. Only a complete equal-output proof permits a speed claim; neither this note nor the existing D9 `SKIPPED` verifier does.
