## Deepest-file plan

- Reuse Storage/Reader, HistoryCatalog, CanonicalClient/CanonicalCache,
  BaseView/Workspace and the daemon overlay owner unchanged. All Store state
  remains global; mutable Workspace state stays under overlay prefixes.
- Add daemon `store/open.rs`: backend-neutral opened providers, fixed read
  handles, one immutable cache, independent Storage producer state on request.
  Synchronization protects a bounded read handle only; no writer gate or
  operation replay. No concrete database or path enters `store/`.
- Add `store/ports.rs`: batched object/length reads and scope serial reservations,
  operation-owned first original errors, and exact demand counters. Ordinary
  reads use only read handles. Whole files and namespaces never accumulate.
- Add `store/bind.rs`: one coherent Branch snapshot; bounded root object,
  root inode path, directory root page and portable metadata validation before
  one overlay Open. Preserve its exact completion on either outcome.
- Add `store/operation.rs` and `types.rs`: shared Workspace base and local
  serials, fresh operation providers/failure custody; declaration-only mod.rs.
- Add daemon `bootstrap.rs` outside `store/`: concrete writer-first open and
  fixed read-only handles, then pass only Storage/History ports into the adapter.
- Add external `tests/installed_store.rs` and fixture helper: real Project Init,
  seal, byte-copy install fixture, reopen; multiple Workspaces on one overlay,
  shared-cache counts, one batch for multiple ids, lengths and disjoint serials,
  original missing-object refusal and healthy independent operation. Cover
  small/large namespaces with bounded bind counts. The fixture copy is not
  product install evidence (F5 remains separate).
- Update daemon architecture/API and core guide in the same checkpoint.
  Existing upstream source remains only until the authorized F12 retirement;
  do not extend or rerun E04. F8 publication and F13 native control follow.
