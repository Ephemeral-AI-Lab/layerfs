## The loop for every stage

1. **Audit.** Parallel read-only subagents establish source facts for the
   stage. They run no Cargo, Docker or test command.
2. **Plan.** The lead writes `checks/<stage>-<date>/01-deepest-file-plan.md`:
   every file to add or change, what it owns and reuses, the frozen interfaces
   between tracks, the proof rows the stage owns, and the decisions taken
   without the owner. Layouts follow the root guide's listing rule. Commit it
   as documentation before any product edit.
3. **Implement** in tracks with disjoint write sets. The lead reviews each
   diff and receipt, then stages and commits each track with its own LOC
   comparison and an honest statement of what is not yet wired.
4. **Integrate.** The lead writes the integrated proofs for the stage.
5. **Review.** Fresh-context read-only reviewers look for what is wrong. The
   lead verifies each finding against source, fixes what is real as a new
   source identity, and records rejected findings with the reason.
6. **Close.** Final suites on host and Linux at the final identity, one run
   per binary; warning-denying Clippy, `fmt --check`, the boundary guard and
   the tooling self-tests; architecture documents, `core/AGENTS.md` and the
   rollout ledger updated; a completion record written in the shape of the
   [R4 record](R4-COMPLETION-20261008.md). Then begin the next stage at once.

A stage whose plan turns out to be wrong gets an amendment committed before
the corrected work, as R4's two amendments were.

**State that must survive loss of context.** This run is far longer than one
context. After every commit, update the stage's row in the rollout ledger with

## Working with subagents

The lead owns the plan, every decision, every commit and every completion
record. A subagent's report is a claim: read the diff and the receipt before
recording anything as done. Write these rules into every brief, because a
subagent starts with no context:

1. One checkout, no worktrees. File ownership is by assignment.
2. Only the lead runs `git add`, `git commit`, `git stash`, `git checkout` or
   `git reset`, counts LOC, edits the ledger or a completion record, or removes
   anything.
3. Each implementing subagent gets an explicit list of files it may create or
   edit. A needed change outside the list is reported, not made.
4. One Cargo, Docker, test or measurement command at a time under the lock. A
   busy lock is not a failure and not an attempt. Read-only subagents run
   none.
5. Every binding instruction above and the preservation list are repeated in
   the brief.
6. Receipts are append-only:
   `checks/<stage>-<date>/<track>-attempt<N>-<binary>.txt`, every attempt
   reported, none deleted or overwritten.
7. A subagent that meets an ambiguity, a conflict with source or a result it
   cannot explain stops and reports. It does not choose a contract point, and
   it does not ask the owner.
8. **Only the lead takes measurements** in R8 and the diagnostic pass.
