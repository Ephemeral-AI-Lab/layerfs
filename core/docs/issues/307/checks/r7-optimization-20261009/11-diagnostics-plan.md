# Stage 0 amendment: authentic bounded observations

> **Status:** Dated planning checkpoint; not release evidence or a product contract.

This plan precedes product edits. At product `2b4dc28a6`, source review finds
534 existing owner numeric fields, five Store demand fields, 13 reader fields,
seven cache fields, ten dispatcher fields, 55 SQL fields per Store session,
31 captured-construction fields and 42 storage fields. None is delivered by the
real binary's ordinary SDK replies. Normal Unmount drops typed opcode visibility
at its wire boundary: it replies with a token while the original local Success
retains the drain receipt. Stage 0 needs these observations, not a new algorithm.

Taken under the owner's direction of 2026-10-09: implement an explicit generic
operator observation of existing controls, with an additive request tag and the
same existing replies. `Request::Observed(Box<Request>)` accepts exactly one
checked layer; nested observations, Hello and EndSession are refused before any
operation. Keep every existing request/reply byte unchanged. Application unwraps
the request, executes the existing operation once and streams credential-free
fixed-schema numeric observations to its existing stderr owner. SDK matching
unwraps the same checked layer. Ordinary calls do no snapshot/format/output work.

Formatting streams directly through a bounded writer; no `format!` collection,
trace registry, log file, extra thread/cache/queue/buffer allowance or persisted
state is introduced. Bound records by the fixed counter schemas and configured
reader population. Counter acquisition errors and partial diagnostic delivery
are explicit unavailable observations. A diagnostic failure never changes the
original publication/unknown/success outcome and never resends an operation.
Preserve diagnostic failure separately with original connection custody.

For final native accounting, clone the existing exact token-qualified
SessionObserver transiently before the original terminal operation and snapshot
it after the operation. It owns no request/lookup/open/reader and must not hold
the registry lock across execution or output. Mount/Attach select their exact
acknowledged token after execution. No past-mount observer is retained. Commit
construction/storage counters come from its original Success/Failure receipt.
SQL session counters are visited one reader at a time instead of allocating a
new aggregate vector. Shared snapshots keep their separate epochs/scope; they
never imply exclusive concurrent-Workspace attribution or exact phase peaks.

The telemetry track owns the bridge request type/codec, SDK reply matching,
daemon Application observation integration, internal control observation helper,
bootstrap per-session diagnostics access, external owning tests and affected
application/native-control architecture documents. Existing canonical Content,
Storage and History contracts and formats are unchanged. No algorithm/count
reduction or measured speedup is claimed for instrumentation.

Physical cleanup has a separate read-only observation. Add a token-qualified
Cleanup request/reply, one owner observation command and one indexed Overlay
point query over namespace/incarnation and existing terminal queue state. It
must not synthesize a mutable Route, retain closed registry entries, resurrect
a Workspace, add an index/table/column, advance cleanup or mutate counters used
as authoritative state. Existing live rows require exact incarnation agreement;
missing rows are Gone only in the current daemon's allocated namespace domain.
Namespace IDs are never reused by a daemon. Refused/missing/stale observations
keep their exact interpretation, distinct from repeating Unmount.

The cleanup track's concrete source/test ownership is assigned separately after
source review of existing namespace allocation/checking. Existing Resources,
DatabaseWork and EXPLAIN diagnostics are reused where available. Kernel syscall
and waiting observations, file residency/size and daemon VmHWM stay external.

Proofs: old/new control codec bytes and malicious nesting, authentic real-binary
diagnostic delivery (no secret output), unobserved zero observation work,
single execution after output failure with exact custody, same terminal drain
facts, bounded records at two unrelated population sizes, exact cleanup against
live/wrong/closed/gone namespaces, existing native/application/control tests.
Build --no-run first; each test <=120 s. Host/Linux Clippy, formatting, guard
and affected architecture updates precede integration acceptance. Fresh-context
review is required; current collaboration tool refused an additional agent with
`agent thread limit reached`, so existing agents will cross-review others' tracks
until a fresh context is available. This limitation will remain in the record.
