Delivered behavior: create/mkdir/symlink/link/unlink/rmdir/rename/chmod/utimens over stable serials, each publishing all inode/name finals in one overlay transaction with one reply-attempt ticket, or nothing. Schema v7 adds an inode's creation generation and a directory's exact visible entry count; both are absolute view facts and stay valid across known install. Workspace evaluates semantics inside the owner job against the rows current in that job, over immutable base facts fetched outside the owner; a round that lacks a fact or refuses writes nothing, and the single publication is the only attempt (no replay). A directory created above the installed floor makes no base demand and settles in one owner round. Removed names keep a whiteout only where a lower row or the base binds them; a name created and removed in one generation leaves no row. Emptiness is the maintained count (base directories use their root-page entry count), so rmdir/replacement needs no enumeration or guard. A directory changing parent proves its destination ancestry by a verified path of at most 256 point steps; opposing moves cannot both publish. Lookup/readdir/readlink handle local directories and symlinks; enumeration returns every name present throughout exactly once and resumes after a partly consumed reply. Serials come from locally consumed 1024-serial ranges reserved through an allocator port; the SDK implements it over the owning history catalog under per-call authority. The daemon runs each round as a typed Mutation-class job; unadmitted jobs return the original command and attempted failures return the exact error.
